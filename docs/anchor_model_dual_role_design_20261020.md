# 錨點作用與品質加權評分服務：雙角色貢獻設計 v1

日期：2026-10-20。狀態：**設計完成，未實作、未執行、未建立有效性。**

後續決定：使用者要求兩角色分開，不合成總分。整合老師原始建議後，目前設計改見 [雙角色實際改善歸因 v2](contribution_dual_role_economic_design_v2_20261020.md)；本v1保留設計歷史，其中50/50合成及品質×服務量主模型分數不再是目前提案。

## 1. 問題與授權範圍

依使用者提出的角色拆分：錨點計算在 custom 搜尋中的作用；模型計算評分服務量，並納入評分品質。只利用一次正常搜尋的原有回覆、固定權重及既有驗證誤差；不訓練替身、不逐人模擬移除、不以歷史 LOO 擬合公式。LOO 只用於離線驗證。

本文件定義的是兩種**程序性貢獻指標**：錨點的改善分帳，以及模型的品質加權服務分帳。後者不是回答對搜尋決策的因果作用。合成分數是明示的分帳規約，不是已建立的完整移除效果估計器。

本次不修改 solver、alpha 初始化／選擇／更新，不做 pruning、付款、Shapley、Notion 或新實驗。所有既有負面結果保留。

## 2. 程式依據與既有證據

`host_server.py:_consensus_loss` 每次對所有評分模型呼叫 api_predict，以 alpha 加權絕對目標誤差。固定成員、正常完成的同一搜尋，各模型這條評分路徑的呼叫次數相同；品質差異不能由次數辨識。

`_solve_subspace_custom` 利用錨點割線或 dynamic 試探斜率合成向量，單位化後試走；目前程式只接受嚴格降低 objective 的步驟，退火是失敗時縮步，並非接受較差解的機率規則。optimization 模式、候選與 alpha 數量相同時，方向權重 a 也使用 alpha。貢獻分析觀察這些固定值，不更動它們。

原生品質權重由 inverse-MSE 建立；近期貢獻實驗則固定 uniform alpha。新設計的品質 q 只用在離線／旁路記帳，即使 q 與 alpha 不同也不能回寫搜尋。

已完成但未建立有效性：純模型方向作用對 full-removal 的平均排名相關 Clean 0.20／污染 -0.04；單步錨點增益對 full-removal 0.25／-0.02；對齊錨點與內部評分後，單步累積對錨點整段效果仍僅 0.06／0.12。來源為 custom_direction_results_20261020.md、contribution_diagnostic_results_20261020.md。本設計延續同一過程分帳家族，不能宣稱加入改善量或模型品質已解決上述失效。

## 3. 輸入與資訊邊界

- 一次 custom-only 搜尋：固定團隊、原 X0、目標 T、box、alpha、方向權重 a、原步長與 secant/dynamic 狀態。
- 每個原有查詢位置的模型回答，查詢目的、呼叫數、輸入樣本數、失敗與耗時。
- 同一固定驗證集上、已在搜尋前保存的各模型 MSE；不新增標籤、不用 pooled/truth。若品質紀錄缺漏、驗證集不同或資料洩漏無法排除，模型品質分數標 unavailable，不能從低搜尋誤差補出品質。
- pooled 僅在分數與所有解鎖定後評品質；truth 只事後診斷。

驗證 MSE 是當前可得的可靠度代理，不是沿途點的真實預測誤差，更不保證跨分布評分正確。

## 4. 錨點分數 A：把當步改善按方向作用分帳

令 ell_i(x)=abs(f_i(x)-T)，L(x)=sum_i alpha_i ell_i(x)，權重均正規化。

對錨點 k，u_kt=(I_k-x_t)/||I_k-x_t||。個別模型沿該方向的原有斜率為：

- secant：b_ikt=[ell_i(I_k)-ell_i(x_t)]/||I_k-x_t||。
- dynamic：b_ikt=[ell_i(z_kt)-ell_i(x_t)]/h_kt，其中 z/h 完全使用 solver 原本查詢的有界試探。

保存雙角色矩陣 v_ikt=alpha_i a_k b_ikt u_kt；錨點列向量 H_kt=sum_i v_ikt；原 solver 合成向量 g_t=sum_k H_kt。不得用重建 g 替換原 solver 的浮點運算結果。

對已接受且實際非零位移的步驟，定義：

    r_kt = dot(H_kt,g_t) / ||g_t||²
    G_t = L(x_t)-L(x_(t+1))
    A_k = sum_(accepted t) G_t * r_kt

精確算術下 sum_k r_kt=1，故 sum_k A_k=sum_t G_t=L(x0)-L(xT)=G。這只證明分帳守恆，不證明因果或外部品質。

r 可負或超過 1，不裁切。A 正值代表對內部改善方向的累計正向分帳；負值代表反向分帳，不代表移除後一定更好。保留 A_plus/A_minus、方向作用原始總量與時間序列，不能只交總分。

實際位移需與原 -g 方向一致；若後續 solver 版本存在非共線投影、不同接受邏輯，不沿用公式。候選太近、邊界零步等按原規則跳過並記錄。

拒絕步不產生 A，但其查詢仍計入服務量。所有接受步 G_t 應 >0；若不是，先判定來源／記錄不符，不靜默裁成 0。

## 5. 模型分數 M：品質加權的評分服務

固定 epsilon=1e-5，沿用原程式已有尺度：

    q_i = 1 / (MSE_i + epsilon)
    N_i = 正常 custom 期間該模型實際成功評估的輸入樣本數
    W_i = q_i*N_i / sum_j(q_j*N_j)
    M_i = G * W_i

另存 API_calls_i、failed_calls_i、elapsed_i，不把批次 API 的一次呼叫誤當一個樣本。原生搜尋目前逐點評分，因此 calls 與 samples 通常相同；任何未來批次化要以 samples 作主服務量。只計 solver 需求的 objective 查詢，不計 Stage 1 品質測試、額外研究 history_metric、pooled、LOO 或重播成本。

重複位置若原 solver 確實重問，計入實際服務；另記 unique_points_i 供診斷。記錄器本身不得多問或改快取。全程或任何模型 API 發生異常，該任務保留失敗，不能因某模型回覆少就給它較低有效貢獻而掩蓋失敗。

M 將本次整體內部改善 G 按「品質×服務量」分攤。**它是服務分帳規則，不辨識誰的回答造成改善。**G>0 時 M_i 不會為負，因此不能識別負模型貢獻。

在目前所有模型共同評分、N_i 相同的情況：W_i=q_i/sum_j q_j。也就是模型排名完全由既有 MSE 決定；不能宣稱這部分新增了沿途貢獻資訊。若 solver alpha 也由相同 q 正規化，W 就等於 alpha；但 M 不回寫 alpha，也不再乘一次 alpha。

可另外保存 B_i=sum_t G_t*dot(sum_k v_ikt,g_t)/||g_t||²，作模型回答對方向的作用診斷。B 與 M 回答不同問題，**不將 B 加到主分數或事後替換 M**；這也讓我們能檢查高品質服務與實際作用是否背離。

## 6. 輸出與可選合成

主輸出是每位的 (A_i,M_i)，並附 N_i、MSE_i、W_i、B_i、正負累計與缺失原因。

如研究需要單一排名，事先固定：

    C_i = 0.5*A_i + 0.5*M_i

因此 sum_i C_i=G。不是 A+M，避免兩個都分攤同一 G 後把總改善算兩遍。0.5 是等分兩種角色的明示規約，沒有理論或老師背書；不依 LOO 結果改成其他比例。主報告仍必須顯示 A/M，不能讓總分遮住角色差異。

C 與 LOO 都是誤差單位，但評分尺、反事實及總量限制不同，仍不能直接以 C−LOO 的 MAE 宣稱精確。C 的正負也不是 LOO 正負。若要用 C 取代 full-removal 排名，必須先獨立驗證。

## 7. 教學例，非實驗數據

假設正常搜尋共改善 G=0.03，錨點累計分帳為 A=(0.024,0.012,-0.006)。三個模型均評分 100 次，MSE=(0.01,0.02,0.04)。略去 epsilon 僅為心算，品質比例約 (4/7,2/7,1/7)。

| 人員 | 錨點 A | 模型 M | 可選 C=(A+M)/2 |
|---|---:|---:|---:|
| 甲 | 0.024000 | 0.017143 | 0.020571 |
| 乙 | 0.012000 | 0.008571 | 0.010286 |
| 丙 | -0.006000 | 0.004286 | -0.000857 |
| 合計 | 0.030000 | 0.030000 | 0.030000 |

丙提供的方向在投影上抵銷，但仍提供一定品質的評分服務；總分負值不等於該人應被刪除。真正算法使用 epsilon，不使用此心算近似。

## 8. 限制與可辨識範圍

同一路徑的觀測無法辨識完全未查詢區域、移除後的新路徑與未來反應；不同模型可在所有已查位置回答相同、在未查區域完全不同，因此程序統計不能一般性保證恢復 LOO。

內部改善不保證 pooled 品質改善；模型可能共同誤判。錨點冗餘、強抵銷、路徑改向、服務被大量重問，都可能使分帳與完整移除不同。q 只是驗證品質代理，分布移動或共同錯誤會失效。M 可能與現有 alpha 排名完全重複；C 的固定等分可能掩蓋角色，不宣稱唯一合理分配。

若 norm(g)/sum_k norm(H_k)<1e-6 或模型列亦強抵銷，標 numerically_sensitive；保存原值但該案不宣稱有效 C 排名。不補 epsilon 到方向分母以偷偷改定義。無接受移動時 G=0，標 no_accepted_motion，A/M 金額為 0但排名不可用，不用全零當有效估計。

## 9. 下一步提案：先技術驗收，再小型探索，未授權執行

### 技術及成本

獨立觀察器不回寫 solver、不改查詢／加總順序。使用既有四個 pilot 案例，各 2 次 warmup、10 次原版／觀察版配對，量 solver+歸因與保存成本；原版和觀察版使用相同模型實例狀態／初始化。觀察版要求原查詢位置／calls／samples／接受／拒絕／切換／交付解完全一致；重建 g、A/M/C 總量採 1e-10*max(1,reference_scale) 容差。零新 API samples，歸因與記錄本機時間額外目標 <=10%，超過則成本門檻未過。

解析測試涵蓋同向、抵銷、負錨點、全部同品質、批次 calls/samples、拒絕查詢、無移動、敏感分母、缺 MSE、history_metric 不混計。不得為過技術門檻改歷史 solver。

### 開發及獨立驗證

開發先用原 20 團隊保存軌跡；若原始逐模型資料不足，就如實標缺並先申明新增正常 replay 成本，不從彙總 loss 反推模型回答。比較固定 A、M、C、舊方向分數，以及單獨 inverse-MSE 排名，離線使用同 custom30/X0 的已保存 full-removal；不新增多輪權重搜尋。A 對 anchor-only、B 對 model-only 的作用研究另列診斷；model-only 若沒有參考，不為這份設計自動新增求解。

開發前必須核對 seed/資料/模型 hash 清單；舊資料結果一律探索。若開發通過才另登錄未用的新 20 seeds×兩情境=40團隊，種子與 hash 在產生結果前鎖定並與所有既有資料排重。新資料模型生成成本另先編預算，不沿用最近失敗或成功確認組冒充未見資料。

獨立組需 40 次正常 custom，以及 160 次 full-removal（3人與5人各20團隊），合計 200 次 solver；其中日後實際算分只有正常的40次。硬上限建議 200 次 solver、250,000 原模型輸入樣本、300秒 solver；模型訓練與離線 pooled 費用分列，執行前完成預算登錄。超限保存不足與失敗，不換 seed 或擴大預算追成功。

### 驗收與停止

- 技術重播通過、0新增模型查詢、有效團隊覆蓋每情境 >=90%；所有未定義／失敗仍留分母。
- 主要效果為 C 與真 full-removal 的團隊內 Spearman，兩情境各自平均 >0.5、seed bootstrap 10,000次的95%區間下界 >0。這是本設計建議門檻，不是老師期望的已知數值。
- 必報 C−A、C−M 的同團隊相關差及 seed 區間；C−M 每情境區間下界 >0，才支持加入錨點統計相較品質服務基準有增益。沒有通過，不能把 q 主導的排名說成正常搜尋觀測的成功。
- 若 M 與 inverse-MSE 同排名，如實標 algebraically_equivalent，不作虛假的統計優越性比較。單獨品質基準差異為0不是新資訊。
- 正負識別僅描述，不作採用或刪人驗收。不得用零閾值分類 C 成為惡意或負品質參與者。
- 任一門檻失敗按負結果停止；不翻號、改0.5、改品質指數／epsilon、挑輪次或加 seed 到過關。另提新假說需新設計與新確認。

獨立驗證者應直接由原始回覆重建 A/M/C，核對 q 僅讀既有 MSE、沒有讀 pooled/truth，重播 baseline/LOO並另載 evaluator 核對排名。測試通過僅證明實作一致，不證明有效性。
