# 學長建議下一步：真正的重複度篩選實驗設計

2026-11-10。狀態：設計提案，尚未實作或執行。目的只回覆學長六（一）4、六（二）5的重複身份疑問，不擴展至一般身份認證、商業市場或alpha選擇研究。原始結果保留；新版獨立建目錄與規約。

## 1. 這次到底要回答什麼

核心問題：Host只用搜尋開始前已取得的錨點與模型預測，能否辨識冗餘提交，使同一實體新增身份不增加合計報酬，同時避免排除相似但有用的誠實模型？

分三層回答，不能用其中一層代替其他層：

1. **辨識**：輸入含重複身份時，是否真的被同一規則分到同群？
2. **分配**：同群只准一個服務席次，是否實際減少分身合計收入？
3. **代價**：正常模型被誤併多少，搜尋品質、可行性與原有預算是否受損？

「知道兩模型一樣，所以直接載入原團隊」不能通過任何辨識驗收。上一輪的restored控制僅是原團隊重播，須在報告持續保留這項澄清。

## 2. 來源與可觀測資訊：先通過資料邊界檢查

核對到的程式事實：

- 凍結`model_step_decision_experiment_v1_20261021/source_snapshot/host_server.py`的`phase1_filter_agents`在原Stage0／Stage1中，確實呼叫`agent.api_predict(self.test_X)`，當時可取得完整預測向量；內部`qualified_reports`也持有residual。
- 反推資格檢查會呼叫`infer_parameters_D`取得candidate，但只在當次局部變數保存；最後`phase1_report`只輸出MSE、bid、inverse_loss、可行性、alpha_pre等摘要，沒有完整預測向量與candidate。
- 目前`custom_realized_gain_v1/runtime.py::load_server`直接載入既有已選模型、候選錨點與固定alpha，沒有重建test_X、test_y或Stage0紀錄。20隊case manifest也沒有盲測點或逐模型盲測原始預測。
- 上一輪`senior_remaining_v1/analyze.py`的`restored=execute(c,load_server(c))`直接重跑原團隊，不是對擴增團隊執行去重。
- `AgentNode`預設bid會隨agent_id變化。新增身份實驗必須固定原bid，否則收入變化混入投標變更。

因此，執行前必須建`pre_search_observation_manifest.json`：

| 欄位 | 用途與限制 |
|---|---|
| task_id、target、box、模型版本與觀測時間 | 防止把不同任務輸出混用 |
| raw_identity_id、anchor、盲測point_ids及signed predictions | 偵測器唯一的幾何／函數資訊 |
| 固定bid、服務資格、原始權重 | 沿用原任務，不由試驗學習新權重 |
| query provenance與model-point成本 | 分辨原流程已有呼叫與本輪重建成本 |
| entity_id、poison／攻擊標籤 | 另存在評估端，偵測器完全不可讀 |

### 歷史與新任務的處理

- **新任務／控制情境**：在原盲測API回應當下留存signed predictions，沒有新模型評分；在反推檢查當下留存錨點，兩者必須發生於原搜尋之前。
- **歷史20隊**：先查原preparation／coalition與建構規約能否唯一重建盲測point IDs、seed與模型版本；只看到MSE不足以恢復完整指紋。來源不完整時標記`presearch_observation_unavailable`。
- 若為歷史測試新指定K個共同點，須明列為「新增事前探測」並計`nK`次模型評分，不能寫成零新增成本。它可作有成本對照，但不符合只使用既有資訊的主版本。
- 不得讀完整原搜尋路徑才挑代表探測點；原搜尋中的未來試探點不屬於Stage1可用資訊。
- 同一批盲測點若原本已具有標籤，偵測器仍只需比較兩模型的signed outputs。pooled、truth、完整LOO結果均不可用於篩選與調門檻。

## 3. 最小候選演算法

### 3.1 兩種距離

錨點以任務box寬度作共同標準：$d_A(i,j)=\sqrt{d^{-1}\sum_r[(a_{ir}-a_{jr})/(u_r-l_r)]^2}$。

模型指紋使用同一組K個事前點：$d_M(i,j)=\max_k|f_i(z_k)-f_j(z_k)|/s_{task}$。其中$s_{task}$是任務開始前公告的共同目標尺度；不得每模型各自縮放，避免將幅度偏差抹掉。若沒有可辯護尺度，保留原始單位並公告絕對門檻。

候選冗餘判斷：$d_A\le\epsilon_A$且$d_M\le\epsilon_M$。缺任一必要指紋時輸出`insufficient_observation`，不擅自排除。

最小兩臂：

- **E：數值等同臂**：門檻只涵蓋重複提交與已測API數值誤差，不把「看起來很像」當同模型。需用同一模型重播估出數值容差，不能讓本批攻擊成功率決定容差。
- **N：近似臂**：預先列有限候選，如共同尺度下1e-4、1e-3、1e-2，僅在開發資料挑一組；錨點門檻亦分開保存。不把多組最好結果當確認結果。

有限指紋相同只表示「在已觀測點難以區分」，不是兩函數全域相同。報告用「觀測冗餘群」而非「證實同一實體」。

### 3.2 分群與代表選擇

不能直接用單鏈connected components：A接近B、B接近C，不保證A接近C，可能把不同模型鏈式併掉。最小版本採complete-link條件，每群所有pair都通過門檻。

先按Host於報名截止前固定的優先序處理；群內選一個代表。優先序使用原任務已公告的服務資格／bid規則，再以Host給定固定tie key解同分；不靠偵測器知道誰是真身。不宣稱此tie key本身解決策略性報名。另測打亂輸入排列是否影響分群；若近似群有歧義，保留ambiguity而不偷偷做最好選擇。

輸出`clusters`、`representative_ids`、`suppressed_ids`、所有pair距離、缺資料狀態及規則hash。下游求解器只能接收這份輸出，不得由測試真實entity映射直接指定原團隊。

## 4. 下游權重與付款政策必須一併寫清楚

篩選改變參與名單，本來就會影響權重與路徑，不能將所有收入變化歸因於指紋準確度。

主政策P1：保留代表原始權重，刪除其他身份後，將保留權重正規化；原alpha值不重新學習／選擇。兩種分身生成方式均測：

- 原實體的原始權重平均拆給兩身份。
- 所有身份在提交後均分權重。

P1在「拆半」情況可能丟掉原實體一半權重，未必恢復原路徑；這是必須報告的政策效果。

敏感度P2：同群只計最大提交權重，再跨群正規化，避免同群權重簡單累加可被分身放大。P2也不能同時保證所有拆分／均分政策的反事實不變性；只作事前固定對照。

不要直接按群內權重總和當主解法：對均分身份規則，新增分身可能增加整群權重。也不要在實驗中使用真實entity_id合併權重，因為部署時Host不知道它。

### 固定預算與服務資格

以原團隊n為基準固定$B_0=100n$、$B_A=B_M=500$，所有方法用相同總預算。代表每人基本報酬100測試單位；剩餘基本池保留，不把多餘預算重新灌給少數代表。未被選入者不產生本任務後續評分義務與基本費資格；這項規則須事前公告。

錨點池和模型池以精確CA／CM、固定F主尺，採原有號累積後截正。雙負取消基本費沿用作歷史可比主臂；Fminus另作固定端點診斷，不同時換評分尺讓作用混雜。無正值時保留整池。

另保留上一輪「固定原基本總額均分當前所有身份」作歷史對照，但不可混入主政策。報酬分別列身份收入、真實實體合計、誠實其他成員、Host保留款。entity標籤只用在最後這層加總。

預算守恆不代表激勵相容；基本費尚未整合真實服務收件事件。

## 5. 實驗矩陣

| 類型 | 提交改變 | 要分辨的問題 |
|---|---|---|
| C0原團隊 | 無 | 偵測器不應憑空刪人；無重複群的回歸 |
| C1完全複製 | 同模型API、同錨點、同bid，新身份 | 是否真實辨識與抑制額外收入 |
| C2只改身份／順序 | C1打亂名單、替換新身份字串 | 是否偷用位置／真身ID，結果是否依輸入順序 |
| C3近似複製 | 輸出加入固定小偏移或事前固定小函數擾動；錨點同時或分別微移 | 模型、錨點兩尺度下的漏檢與收益 |
| C4相似誠實模型 | 獨立模型在盲測點接近、在部分搜尋區域不同 | 是否誤併有用模型；不能把相似等同惡意 |
| C5有限指紋反例 | 事前觀測點完全相同、觀測外不同的解析函數 | 有限既有資訊的辨識極限，避免宣稱全域同模型 |
| C6缺資料／非有限值 | 缺一個點、模型改版本、NaN、不同點集合 | 是否正確拒絕做判斷，而非自動刪人 |

C3擾動幅度以事前共同尺度固定，不能按確認集結果挑幅度。C4「有用」僅在所有端點鎖定後由離線pooled品質差判斷；不要先看外部品質挑容易通過的案例。C5已知解析品質只作診斷，不進入篩選器。

同一原團隊、起點、solver預算作配對：無篩選、E、N。各臂從空任務快取開始；共同Stage0基礎成本每臂都列，篩選本身向量運算不算模型呼叫，缺失資料補探測要另外列。

## 6. 先小型開發，再決定是否獨立確認

### D0：工程與資料可用性（先做，沒有這步不跑大矩陣）

- 完整讀原preparation與seed來源，產出20隊資訊可用性表；不能只抽一隊就推論全部。
- 六個微型fixture：完全複製、近似門檻兩側、鏈式相似、相似誠實、缺資料、輸入順序。
- 在4個歷史團隊（兩情境各2）做C0/C1、兩權重政策、無篩選/E對照；至多32個30輪路徑。未重新訓練模型。
- 工程上限：10萬新增參與者model-point評分、2千離線pooled評分、120秒；達上限保留partial，不能事後刪掉昂貴失敗隊。若歷史指紋不可恢復，D0先交付資料缺口並轉解析新任務控制，不用全程路徑補假指紋。

### D1：方法開發

4個歷史團隊只作回歸；另12個新解析團隊（n=3/5、一般／相似模型／局部差異等），事前固定seed與生成規則。用C0–C6決定E數值誤差範圍及最多一組N門檻。所有開發失敗保留。

歷史模型可驗證實際非線性模型的操作，但新的解析seed仍只能支持機制，不等於新實務模型外部確認。

### H：條件式獨立確認

D1後鎖碼、門檻、代表規則與付款政策。另32個未讀取的解析團隊，依相同生成族分層；不同seed必須事前寫入manifest。C0/C1/C3/C4主矩陣，預定兩種身份權重政策、無篩選/E/N；成本上限150萬參與者評分、1萬pooled評分、900秒。此為工程上限，不是已量測成本。

確認若失敗不再拿同批調參後重標確認。新訓練模型／不同任務屬下一階段，需另開規約與預算；目前不啟動大型訓練。

## 7. 主要指標與探索驗收

以下是建議的探索參考，尚未獲老師同意，必須在看確認結果前鎖定：

1. C1完全複製辨識率100%；不得讀entity標籤。缺資料案例應明確拒絕判斷。
2. C0無冗餘時，名單、權重、完整求解結果與精確分數重播一致；模型輸出比較依float規約，而非單純JSON長度。
3. C1固定總預算下，同實體增收不得超過取整容差；連續金額主分析容差1e-8，整數分配另外核對1單位差。任何確定獲利反例即否定「本設定抗完全分身」主張，不以平均負收益掩蓋。
4. 近似臂必須分開報「攻擊漏檢」及「誠實誤併」；暫以誠實誤併<=5%作探索參考，不憑幾十個案例宣稱統計證明。品質退化用配對差、最差例與退化率呈現；暫以超過預定品質容差的退化率<=5%作參考。品質容差需依原任務尺度在D1凍結，不能看H結果後調。
5. 報實體增收分布、max／p95、每池收入、其他誠實者收入及保留額，不只報分類正確率。
6. 報模型呼叫總數、篩選新增、原搜尋、貢獻計算、離線pooled各項；向量距離運算的CPU時間另外量。
7. 分群不唯一／只有一名代表／無有效團隊均保留為失敗狀態；不能拿單模型CM除以零，也不能無聲省略。

停止條件：來源／時間邊界錯誤、偵測器接觸entity或pooled、預算不守恆、C0重播不一致、非有限估計立即停止。若E不能抑制完全複製，先查篩選到付款鏈路與權重政策，不進N門檻搜尋。若N降低分身收益但大量誤併有用誠實模型，停止採用N，只保留負面結果。

## 8. 建議實作介面與證據產物

新增獨立套件`contribution_analysis/senior_identity_screen_v1/`，不要修改凍結solver：

- `observations.py`：只匯入時間邊界前的輸出，計資料來源與成本。
- `screen.py`：`screen(observations, rules) -> clusters, representatives, statuses, pair_metrics`；禁止接收模型參數、entity標籤或品質評估物件。
- `policy.py`：代表權重、固定基本池、保留款與服務資格；真實entity映射不得進入。
- `run.py`：由篩選結果實際建新的server輸入、沿原切線／割線法跑、精確CA/CM計分。
- `audit.py`：另一條讀取路徑重建保留名單／權重／付款；檢查被抑制身份沒有偷偷被呼叫；接入評估端entity映射核算獲利。

`attempt_01/`至少保存registration、source_lock、observation_manifest、raw_public_observations、screen_decisions、post_screen_solver_manifest、query_ledger、endpoints_locked、offline_quality、identity_payments、entity_payments、audit、failures。

必要測試不應只是重寫演算法：以一個非原始ID當代表、打亂順序、抹除entity欄位，再驗證實際server的模型列表確實變動；故意讓分群形成A–B–C鏈，驗證不被單鏈併掉；將C1指紋保持相同但改eval側entity標籤，篩選輸出必須完全不變。

## 9. 推薦最小下一輪與可以收尾的條件

先只實作**資料邊界＋E數值等同篩選＋固定基本費上限**，跑D0。它能最快回答「真正把重複提交擋在服務開始前，是否修掉已知獲利案例」。若這條完整鏈路通過，再測近似篩選的誤傷；不要同時改自評尺、貢獻定義、N與抽查方法。

若完全相同指紋但觀測外不同的C5反例顯示無法分辨，應明確收尾為「既有有限資訊只能控制可觀測冗餘，不能證明同一實體或全面抗分身」。這是可向學長報告的研究結論，不需要為了零攻擊報酬而任意增加新資訊。
