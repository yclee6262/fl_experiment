# 單步錨點增益累積：效果與成本實驗結果

日期2026-10-20。依使用者授權執行`local_anchor_step_value_proposal_20261020.md`；計算前以`local_anchor_step_preregistration_20261020.md`固定方法、樣本、比較與停止條件。

## 結論

**這個版本比完整LOO省成本，但尚未取得可靠的LOO品質排序。** 舊資料探索的平均團隊內Spearman為Clean 0.25、污染-0.02，探索性95%區間均跨零。相較上一版推力S的0.20／-0.04，點估計只多0.05／0.02，配對改善區間也跨零，不能宣稱穩定變好。

成本優勢本輪有直接證據：20個探索團隊，正常求解加本方法需12,287個模型輸入評估，正常求解加完整LOO需33,120個，**省62.9%**。另以4個pilot作同機、每方法每案15次交替配對，包含重新載入模型的流程耗時約省68.4%，計入範圍的核心運算約省75.0%。成本範圍不同，不能把4pilot耗時比例當20案全體的實測端到端加速。

因此成本門檻通過、效果門檻未過，依登錄停止；沒有改步長、正負號、累積權重或追加資料。這是10個舊seed／20個探索團隊／80個效果，另4pilot／16效果分開，不是新獨立確認，也不回填P3或前一輪結果。

## 初學者版：這次實際試了什麼

對每個原本已接受的custom步驟，固定目前位置、原本接受的距離、全部模型與評分權重。每次只少用一個錨點來合成替代方向，試走相同距離。

- 若替代步更差，原錨點得到正增益。
- 若替代步更好，原錨點得到負增益。
- 若替代步不比原位置好，就按照接受規則留在原位置，不能把被拒位置當交付結果。
- 每個錨點跨步直接加總signed增益，保留正反明細，不再乘步長、不把總和強迫設為1。

精確主公式：

`J_kt=min(L(x_t), L(z_without_k,t))-L(x_(t+1))`

`A_k=sum_(原軌跡接受步t) J_kt`。

其中L一直是原團隊、原alpha的內部搜尋目標，pooled與truth沒有進入J或A。拿掉的只有錨點方向分量；其提供者的評分模型仍在。單步反事實不接續新路徑、不重新退火，也不等於完整參與者移除。

## 執行與技術驗收

原始資料取自`custom_direction_experiment_v2_20261020`：4pilot與20探索的固定模型、custom30已接受軌跡、方向分量及既有逐模型回覆。沒有重訓、新資料或alpha更新。

1. 凍結11項測試通過：方向與剩餘權重、替代拒絕留原位、替代較好負分、無方向、box不裁切、單錨點、缺回覆／float32快取、signed累積、skip anchor及無接受步狀態等。
2. 對24條軌跡的992個「錨點×接受步」組合算分；全部可作等距比較，沒有邊界不可比、缺步或無方向棄權。pilot109組、探索883組。
3. 每迭代重用原查過的完整回覆；探索組6組命中快取，其餘877組新查詢，pilot109組全部新查詢。scalar API口徑與原LOO一致，沒有用batch呼叫數掩蓋樣本量。
4. 全部24案A與原始回覆先hash鎖定，再讀現成、同一custom完整移除C與上一版S。不載入pooled模型或truth作新算分。
5. 獨立驗收不用配分kernel，從原方向與保存回覆重建替代位置、接受／拒絕、J及A、快取來源與排行。最大J重建差5.55e-17；24案、96人次、992組全部核對通過，來源／舊結果hash未變。
6. 成本配對流程再由原solver正常求解，確認新baseline的解與查詢hash不變、A與離線首次計算一致、重算LOO解與原custom參考一致。

驗收通過證明實作及比較可重建，不證明累積增益就是完整品質貢獻。

## 與LOO效果差多少

參考為固定已訓練模型／起點／custom30的完整移除：移除I_i、f_i及alpha_i，剩餘權重正規化，依原程序求出完整解，再由固定pooled離線評分：

`C_custom_full,i=E_pooled(X_without_i)-E_pooled(X_full)`。

本輪直接重用已驗收的相同custom參考，沒有混用best_of。額外成本測試的重算LOO也沒有產生新訓練或調整方法。

## 成本比較：實際查詢量

下表為20個探索團隊，每團隊正常解只算一次；不把計時重複執行混入算法成本：

| 工作 | 模型calls | 輸入samples |
|---|---:|---:|
| 共用正常baseline | 8,448 | 8,448 |
| 新方法額外單步查詢 | 3,839 | 3,839 |
| 完整LOO額外查詢 | 24,672 | 24,672 |
| 正常baseline＋本方法 | **12,287** | **12,287** |
| 正常baseline＋完整LOO | **33,120** | **33,120** |

總量省62.9%；只比較額外歸因工作，本方法是完整LOO的15.6%。相對不計貢獻的正常baseline，仍增加45.4%，不是幾乎免費。原提案上限3,869，實際3,839，差異是6次float32快取命中、各省5個模型輸入。

分情境總量節省：Clean55.6%、污染65.0%，均超過本輪50%目標。本方法不是上一版0新增查詢算法，不能沿用它的8.71%耗時或10%目標宣稱低成本。

## 成本比較：同機完整流程實測

每方法每案2次warmup及15次計時，交替順序。每次都重新載入同樣模型、建立節點、正常求解；本方法含原始方向記錄及單步歸因，完整LOO含所有成員移除求解，兩者重用已載入模型。這裡的重新載入不是清空作業系統檔案快取的冷磁碟測試。

| pilot案例 | baseline＋本方法流程中位數 | baseline＋完整LOO流程中位數 |
|---|---:|---:|
| Clean／2026101600 | 12.86ms | 30.54ms |
| Clean／2026101601 | 13.21ms | 32.37ms |
| 污染／2026101600 | 19.49ms | 74.49ms |
| 污染／2026101601 | 18.88ms | 66.82ms |

各案中位數相加：本方法64.43ms、完整LOO204.22ms，流程比0.3155，**約省68.4%**。若只計正常求解＋記錄／歸因／LOO，不含載入，分別46.52ms／185.89ms，約省75.0%。這是4個固定pilot、本機CPU單執行緒、2D、m=3／5；不含pooled、結果寫檔或網路服務，不能推論遠端與大型場景必然同速比。

探索20案另有每案本方法首次讀取／載入／查詢／寫完整紀錄的端到端時間，合計約0.268秒；舊LOO未保存同範圍的全端到端時間，所以不拿不同範圍硬算20案的端到端加速。歷史core與本輪core的20案合計比較另保存在`case_costs.csv`，屬跨次運行參考；主要耗時結論採上述同機配對實測。

## 研究成本與記憶體／儲存

首次24案配分共新增4,306 scalar API calls／samples（pilot467、探索3,839），沒有新solver；核心約0.147秒，包含讀紀錄／模型載入／寫檔的首次工作約0.863秒，第一案例包含一次性初始化。

計時／memory warmup及配對流程共408個新custom求解。含首次配分的本次所有研究工作合計143,315 calls／samples、核心約4.949秒，配對階段wall約6.160秒；這些包含重複計時與warmup，不能當作單次部署歸因成本。原20案LOO品質參考直接讀取，沒有為主效度重新訓練或生成資料。

24份完整單步紀錄約1,101,557 bytes（探索979,580、pilot121,977），另有摘要、計時及圖表。每案`*.timing.json`保存實際record bytes、process RSS高水位、各階段耗時。首次流程process RSS最大約201.4MB，包含Python／PyTorch、已載模型及先前案例，不是歸因單獨的增量記憶體。

pilot首個warmup另外以tracemalloc量Python配置峰值：本方法首案約12.67MB（含首次AST／inspect等初始化），後三案約0.26–0.41MB；完整LOO約0.19–0.26MB。tracemalloc不完整涵蓋PyTorch原生tensor，且原型保存完整軌跡而LOO只需結果，不能宣稱本方法也節省記憶體。這些memory warmup不納入上述15次計時中位數。

## 研究狀態與解讀

**已完成：**固定公式與來源、11測試、992組局部反事實、24案分數鎖定、96效果比較、四pilot同機配對、查詢／時間／儲存記錄、獨立重建與圖表。成本門檻通過。

**未建立有效性：**逐步錨點增益加總能可靠反映完整參與者LOO品質，或比上一版有穩定改善。效果門檻未過，`gate.json=exploratory_screen_not_passed`。

局部J沿原路徑、固定全部評分模型、使用內部L；C移除候選與模型、改變後續路徑、使用pooled。跨步A還可能重複計入相似作用，沒有總改善可加保證。本輪沒有分離這些差異各自造成多少落差，不能指定單一原因，也不能僅靠多一層加權就宣稱解決。

**下一步提案：**先保留此版本作「局部錨點增益」分析工具；若續研，另登錄診斷以區分局部與整段、候選與模型角色、內部L與外部品質的差異。這些是待決研究問題，本次未執行。按原門檻停止，不追加seed、調分數或啟動新確認。

沒有alpha初始化／選擇／更新、pruning、付款、Shapley、Notion或商模工作；舊正式及負面結果均保留。
