# custom實際方向的模型作用累積：方法與驗證設計

日期：2026-10-20。依使用者要求設計「custom找出實際搜尋方向時，各模型的作用逐步累積」的方法。此文件是設計稿，尚未實作記錄器或執行模型實驗，不是老師已認可或已建立有效性的方法。

執行後更新（2026-10-20）：本方法已依使用者授權完成實作及小型探索，技術／成本通過、品質排序未通過；見 [實驗結果](custom_direction_results_20261020.md)。以下保留執行前設計；凍結副本另存於實驗目錄。

## 1. 本輪精確研究問題

**在同一次custom求解中，各local model的評分資訊，分別推動或抵銷了多少實際被接受的搜尋位移？累積作用的高低，是否能反映同一custom程序的完整移除品質排序？**

主方法命名為「模型方向作用累積」（Model Direction Attribution，僅本研究工作名稱）。先量測本次程序中的模型角色，不把它直接叫作完整參與者品質貢獻。

與前一輪不同：前一輪事後估計grad ell_i，再乘實際位移，觀察個人目標如何被改善。本方法分解`host_server.py:_solve_subspace_custom`本來就拿來決定方向的secant／dynamic向量，觀察更新生成來源；不另估模型真梯度、不沿個人loss做線積分、不從歷史LOO學規則。

邊界：模型、團隊、候選、alpha及起點規則保持固定；不改alpha初始化／選擇／更新，不做pruning、付款、Shapley或Notion。pooled只在解和分數鎖定後評品質，truth只作診斷。

## 2. 將實際搜尋向量依模型分開

用i表示評分模型，用k表示候選方向提供者。兩個索引必須分開，即使是同一批參與者。

- 現在位置：x_t；候選點：I_k；目標：target。
- 個人誤差：ell_i(x)=abs(f_i(x)-target)。
- 評分權重：alpha_i；方向權重：a_k；均使用該次solver已固定、已正規化的值，不重新選權重。
- 目前各方向：u_kt=(I_k-x_t)/norm(I_k-x_t)，與原程式相同地跳過太近的候選。

secant模式下，各模型在每個方向的斜率部分是：

`b_ikt = [ell_i(I_k)-ell_i(x_t)]/norm(I_k-x_t)`。

dynamic模式下，用原solver實際查詢的有界位置z_kt=x_t+h_kt*u_kt：

`b_ikt = [ell_i(z_kt)-ell_i(x_t)]/h_kt`。

跳過規則沿用原程式（候選距離<1e-8、dynamic步長<=1e-12），不另補查位置或平滑loss。

定義原始分量：

`v_ikt = alpha_i * a_k * b_ikt * u_kt`。

第i個模型對整個搜尋向量的作用為：

`g_it = sum_k v_ikt`。

全部模型合成：

`g_t = sum_i g_it`。

在精確算術下，這等於原custom程式合成、但尚未單位化的gradient變數；它是方向斜率合成向量，不宣稱是真梯度。浮點加總順序可能產生小差異，記錄器必須用原solver的g_t作觀察參考，不拿重建值回寫或驅動求解。

這裡的g_it包含第i模型對**所有候選方向**的評分作用，不只是它自己候選方向。若把g_it錯寫成alpha_i乘第i候選方向，就會混淆模型角色與候選角色。

## 3. 先重建每一步的位移來源

原solver先把g_t單位化，再試步／縮步／限制box。最終接受步長為s_t，則：

`delta_x_t = -s_t * g_t/norm(g_t)`。

在不改原來步長與normalizer的條件下，將這一步分解為：

`delta_x_it = -s_t * g_it/norm(g_t)`。

可檢查：`sum_i delta_x_it = delta_x_t`。

這是固定已發生決策後的一種可加分帳。移除某人後normalizer、方向、試步、接受及切換都可能改變，故delta_x_it不是移除反事實；也不宣稱此分帳是唯一的因果分解。

## 4. 轉成可逐步累積的signed分數

不能直接把向量的各維相加，也不使用norm(g_it)當貢獻，因為方向相反的強作用也會有很大的norm。

先把模型位移分量投影到該步實際移動方向：

`d_it = dot(delta_x_it, delta_x_t/norm(delta_x_t))`

`     = s_t * dot(g_it,g_t)/norm(g_t)^2`。

- d_it>0：該模型的方向分量與最終實際方向同向。
- d_it<0：該模型分量與最終方向相抵銷；這不等於模型錯誤、有害或品質負貢獻。
- d_it約0：在此投影下沒有淨推力；仍可能有正交分量，移除後可能改變方向，因此不等於無用。

只對**實際被接受、位移非零**的步驟累積主分數：

`D_i = sum_(accepted t) d_it`。

另分開保存正向總量D_i_plus、反向總量D_i_minus（負值原樣保留），D_i=D_i_plus+D_i_minus，避免看不到互相抵銷。

同次任務的總接受路徑長為P=sum_t s_t，定義主要比較分數：

`S_i = D_i/P`，僅在P>0且數值可靠時定義。

**主要輸出：D_i（方向上的signed距離）及S_i（該次任務的signed相對作用）。** 後續與LOO排序比較固定使用S_i，不從結果挑權重公式。S_i在單一coalition內與D_i排序相同，除以P只移除共同路徑長尺度。

在精確算術且所有步驟可分帳時，sum_i D_i=P、sum_i S_i=1。S_i可以小於0或大於1，不裁切、不轉成付款比例。

只累積norm(delta_x_it)會把阻力也計成正分；把所有步等權累加方向比例，則會讓極短小步和長步影響一樣。使用實際接受步長的投影累積，正是為避免這兩個問題。它仍是路徑長作用，不是最終淨位移或品質改善；路徑繞遠也會被計入，另報路徑長／起終點距離，不將繞路解釋為高品質。

### 一維小例子

若某步g_甲=3、g_乙=-1，合成g=2，接受向左0.1：

- 甲的位移分量=-0.15，對實際左移的作用d_甲=+0.15。
- 乙的位移分量=+0.05，作用d_乙=-0.05。
- 合計位移=-0.10，作用總量=0.10；該步相對作用為150%與-50%。

意思是乙抵銷一部分甲的推力，不是乙一定讓最終品質變差。兩人若一起指向錯誤方向，本方法仍會忠實記錄「誰推動了那個方向」。

## 5. 機制範圍與特殊狀態

1. **接受與拒絕分開。** 接受步才加D。所有失敗試探、縮步、原始斜率、模型回覆、secant到dynamic切換與停止原因都保留。拒絕步記為未產生已接受位移，不解讀為其資訊沒有價值，也不另外發明拒絕獎勵。
2. **共同步長不配給個人。** 本方法暫時分解方向生成，沿用實際接受的共同s_t；沒有完成步長／接受門檻的個人歸因，不把整個接受決策都宣稱已分解。
3. **強抵銷。** 記rho_t=norm(g_t)/sum_i norm(g_it)，以及sum_i abs(d_it)/s_t。g_t很小但各g_it很大時分數可能極大，這是條件不穩，不可靜默裁分。原solver norm(g_t)<=1e-8仍照原規則停；觀察器另以rho_t<1e-6標為數值敏感，不改solver。只要有被接受的敏感步，保存原始分數，但該案對外S標`numerically_sensitive`，不宣稱可靠排序。1e-6是本設計的技術警示值，不是資料調出或老師指定的有效性門檻。
4. **沒有接受步。** D定義為0；P=0時S未定義，回傳`no_accepted_motion`，不能補成每人0或均分假裝有效估計。
5. **候選與模型不重複計。** 保留完整i×k分量作audit；可按候選欄加總作診斷，但不能把候選分數加上模型分數當同一人的完整貢獻。本輪主分數只按模型列加總。
6. **固定alpha是條件。** 某模型作用小可能只是原程序使用它較少，並非其本質品質差。alpha_i不能另加成貢獻獎勵。
7. **best_of界線。** 主研究採custom-only程序，baseline與LOO都用同樣custom設定。若未來在best_of中只記custom，當SLSQP勝出時此分數不是交付解的來源，須標`engine_mismatch`，不能自動套用。這一輪不把SLSQP更新硬套custom公式。

## 6. 與LOO能比較什麼

參考須新建為同一custom程序的：

`C_custom_full,i = E_pooled(X_custom_without_i)-E_pooled(X_custom_full)`。

固定已訓練模型、box、target、原保存X0、custom30及其退火／切換設定。移除候選I_i、模型f_i及alpha_i，將剩餘alpha正規化，依原程式也相應得到剩餘方向權重。沒有重訓或重做招募。輸出解先保存，才由另一離線程序載入pooled評分。

既有80案C_full主要來自best_of，**不能不重算就改稱custom-only參考**。可重用其模型、團隊與候選，卻要以新目錄保存custom baseline／removal結果；不同反事實另列。

主比較是**每個團隊內的模型作用排序，是否對應完整移除品質效果排序**。S與C單位及定義不同，不用S-C的MAE當主要驗收，也不使用歷史C擬合尺度。

特別注意：sum S=1，使S必有正值；C則可能全為負或全近0。因此零閾值不是兩者共同的語義，S<0不能直接當C<0。若報正負一致或負值識別，只作描述，不能把這個分帳定義包裝為全體signed品質效果估計器。

還有角色差異：S只分解模型評分角色，完整移除同時刪候選角色。關聯弱可能是角色／路徑改變，不足以證明代數分解有錯；但也不能因此宣稱S可替代完整移除。必要時日後另立「只移除模型、保留候選」診斷，不能與完整移除混報，本次不自動擴充實驗。

## 7. 最小實作與實驗提案（尚未執行）

### A. 觀察器先驗收

在獨立版本／凍結來源中加只觀察的記錄點；原solver用的g、s、接受判斷、alpha、呼叫順序與浮點運算順序都不回寫。從既有objective每個模型的回覆取ell，保存候選點回覆、當前回覆及dynamic試探回覆；不為補記錄重問模型。

每輪保存x、模式、跳過方向、u、b、g_it、原始g、每次試步及結果、實際接受步長／位置、rho、d、停止／切換原因。實作可不常駐全部v_ik向量，但要有足夠原始回覆讓獨立驗收重建i×k關係。若缺回覆，該案例失敗，不能填0。

技術測試至少包含：同向／反向一維解析例、非共線二維例、正交分量、強抵銷、無位移、邊界縮步、secant轉dynamic與被拒試探不計已接受距離。核對向量總和、實際位移重建、投影總和及P總量關係。

原solver對照記錄版：模型API calls及輸入samples完全相同，試探順序與接受／拒絕／切換相同，交付X最大差<=1e-7、loss差<=1e-10；重建向量／位移／總量用`1e-10*max(1,reference_norm)`絕對容差。不能為過測試用重建g替換原g。

- pilot每案再作逐人custom full-removal，合計16次移除。pilot資料只作技術／設計開發，不與探索組混稱獨立確認。
- 舊資料探索：沿用預算研究10個保存seed、兩情境共20案例，m=3／5，custom baseline20次、完整移除80次，共100次。原模型／候選／X0直接重用，不重訓。
- 合計上限244次custom求解、500,000模型輸入samples、300秒solver；超限保存部分與失敗，不換seed湊通過。這是後續執行預算提案，尚非已產生成本。
- 所有baseline先保存原始分數／hash，再產生其移除解與讀取pooled。計算式／警示閾值不得看探索結果後調整。

### C. 比較、門檻與停止

固定主分數S；固定比較為按原alpha排序的基準（uniform時全tie，相關記未定義、不補0假裝有排名），以及候選欄作用的診斷。主方法不能根據哪個結果好就改成候選分數。另報全部C、作用正反總量及rank有效率。

探索主指標：各情境每團隊Spearman(S,C)的平均值與分布，seed群組bootstrap10,000次、探索性95%CI；同時報可計團隊數、LOO近乎全平或S全tie的原因。每團隊有效參與者至少3；有失敗／敏感／缺標籤時該團隊不算有效主相關，仍完整列入分母與原因，不挑個人刪除。主分析不靠跨任務pooling的Spearman取代團隊內表現。

可考慮進入新資料的固定探索條件：技術驗收通過、0額外模型calls／samples、記錄＋歸因耗時目標<=原custom的10%；兩情境各自至少90%團隊可有效評估、團隊內平均Spearman>=0.5且探索95%CI下界>0。門檻為本設計建議，不是老師指定，也不等於正式有效性確認。若uniform基準全tie，如實報無排名，不宣稱已統計優於它。

上述任一未過，停止且交付結果，不改權重、正負號、閾值、累積規則或追加seed到過線。即使過關，也只能說「舊資料顯示可能有排序資訊」。之後另登錄新的模型／資料／evaluator確認組，查seed與資料獨立性；未取得獨立證據，不作部署貢獻規則。

## 8. 成本與仍未回答的問題

新方法只攔截原本會取得的回覆，目標新增model API calls／samples=0；不等於實作已達成或計算免費。m個方向各有m模型回覆，重建g_it約O(m^2*d)／次方向迭代，保存回覆約O(m^2)，完整研究軌跡另隨迭代／試探數增加。實作可串流累積D與正反總量，但研究驗收仍須保存足夠原始證據。高維、多模型、遠端服務的成本另驗證。

仍未回答：方向作用是否與品質排序一致？候選角色／交互作用佔多少？方向分帳漏掉多少接受／停止決策作用？強抵銷是否常見？迂迴路徑是否使累積失真？custom-only結果能否適用原best_of交付？這些都不能靠代數總量相等直接回答。
