# 單次 B 後選擇性增加 Uniform 候選：開發與重播紀錄

## 問題、規則與資料邊界

目標是讓額外 Stage 3 求解只發生在單次 B 看起來較不可靠時。B 是既有 Stage 0 blind-test MSE 反比權重；Uniform 是所有人等權。兩種 α 均使用 `|Σ_i α_i f_i(X)−T|` 的 Stage 3 目標。方法先求 B 的 X，再用既有 20 筆 Stage 0 blind labels 擬合 B20 ridge residual calibrator，計算 B 候選的校正後內部 target 誤差。若 B 求解失敗、無法內部評分，或該誤差**嚴格大於 0.01**，才額外求 Uniform 候選。兩者都有效時，以同一 B20 calibrator 的內部誤差較低者交付；平手留 B。Stage 2 proposals、候選子空間、box 限制及求解器固定。B 的內部預測在決策後直接重用，不作第二次 API 查詢。

0.01 門檻是在查看舊資料後提出的**開發規則**，沒有預先登錄，因此所有下述區間僅供描述，不能作確認性優勢宣稱。pooled evaluator 與合成 truth 僅在選定 X 後載入評分，從未進入觸發、α、求解或選解。這個方法改進的是**初始 α 候選的計算配置**，不是新的單一 α 公式，也不是從頭移除參與者。

使用既存模型、資料、proposals 和 evaluator 重新執行序列流程：低品質 25% 情境 seeds 2600–2629、乾淨基本與 4× 樣本量不平衡情境各 seeds 3000–3179。乾淨／不平衡 seeds 曾用於另一項正式研究；本規則對它們的評估仍是**事後探索**，不能把這 360 筆改稱新正式測試。`run_adaptive_alpha_replay.py` 每 seed 完成即落盤；失敗狀態及已消耗請求保留。`analyze_adaptive_alpha_replay.py` 逐 seed 核對已存 B／Uniform 候選的 X、pooled 分數與 Stage 3 請求量。

## 實際重播結果

主要差為 `E_adaptive−E_B`，負值代表自適應法的 pooled 絕對誤差較低。成本是 Stage 3 加候選選擇 local-model API 請求；單次 B 沒有選擇請求。五候選的成本亦含既有選擇請求，未加計其他額外初始化成本。所有方法的共同資料、模型及 Stage 0 準備成本未重複計入。下表的 95% 配對 bootstrap 區間使用 seed 為抽樣單位、10,000 次重抽樣；因規則及資料已被探索，**一律不得解讀為正式顯著性檢定**。

|---|---:|---:|---:|---:|---:|---:|

| 乾淨基本 | 180／180 | 69；29 | −0.000532 | [−0.001179, +0.000072] | 23／151／6 | 476.25／344.38／1,711.27 |

相對新目標五候選，自適應方法的 pooled 平均差依序為 **−0.000348、+0.001127、+0.000762**；低品質的描述性區間跨零，乾淨情境則明確偏向五候選較好。自適應法節省約 **72%–73%** 的 Stage 3＋選擇請求，但比單次 B 多約 **38%–50%** 的請求；本地 API 請求數不能直接當成遠端金額或延遲。沒有定義每次查詢價格、每單位 pooled 誤差的價值、允許的尾端退步前，不能稱此法貨幣效用較高。

390／390 個交付 X 均有效且 box 可行；與既存候選紀錄的 X、pooled 分數及 Stage 3 請求量最大差均為 0。這證明重播及成本歸屬一致，但既存候選紀錄不是新的盲測資料。當 B 已有有效 X 而 Uniform 求解失敗時，流程仍保留 B；若兩者皆失敗，交付為 solver failure，不能交付違規 X。

## 下一步門檻

低品質情境出現值得驗證的**品質／成本折衷**，但平均收益集中在少數改由 Uniform 交付的 seeds；乾淨與不平衡情境沒有穩定優於 B 的確認性證據。下一步若要正式檢驗，需先封存 0.01 規則、來源與成本口徑，使用未參與本輪設計的新 seeds；事前同時規定 pooled 品質、失敗率、請求成本與尾端退步的判定。若經濟價值是主張的一部分，應先給定 `c/v`（單次查詢成本／每單位 pooled 誤差的價值）或可容忍品質損失，否則只能報品質—查詢量前緣。
