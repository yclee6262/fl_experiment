## 本次發現的具體缺漏

### 1. 失敗案例仍不能完整保存與分析（立即可修，正式執行前優先）

- `p6_budget_pilot.py` 的選人呼叫在局部 try/except 外；無可行集合會中斷整個 run。倒推失敗列缺少 selected IDs、bid、quality 與 Stage 3 成本等欄位。
- `analyze_p6_recruitment.py` 在配對時直接讀取成功解的品質與 selected IDs；失敗列會造成缺欄／空值錯誤。`box_infeasible` 亦把 box_feasible=False 的 solver failure 合併計入。
- `analyze_p5_results.py` 的部分 evaluator 欄位在 solver_failure summary 不存在；即使有效品質篩選存在，彙總仍可能失敗。缺少的成本以 0 代入，也可能低估失敗成本。
- P5 分析只檢查 A/D seeds 互相一致，沒有檢查預定 seeds 全集；雙方同時缺同一 seed 可漏檢。以 dictionary 建索引亦需拒絕重複鍵。
- `verify_validity_pilots.py` 主要確認本批全成功資料，固定 5 seeds，來源快照僅驗存在；它不是可容納真實失敗的通用驗收器。

修正規劃：建立固定結果 schema；qualification failure、無可行招募、solver failure 與有效交付分開；保存失敗成本；按 manifest 驗方法×seed×情境完整性；用人工注入失敗、NaN、重複及缺失列測試分析器。驗收是「保留失敗並完成報告」，不是要求所有資料永遠成功。

### 2. 成本口徑尚不完整（立即可修；新增成本需新 pilot）

P6 的計數器在 `build_base_server` 完成後才掛入，因此 `selection_precompute_requests=10` 僅計 `qualified_candidates` 重算 residual 的呼叫，沒有包括此前 blind-test、inverse qualification 與模型訓練。正式 proposal 產生的時間也未獨立保存。`inversion_seconds` 還涵蓋參數 deepcopy、evaluator 評分等操作，不能稱為純 solver 時間。

規劃：分開記錄訓練、資格檢查、proposal、residual 預計算、選人、倒推、外部評分；另分 API calls 與本地梯度／前向計算。共用成本每 seed 計一次，提供每方法假想獨立執行與整批攤提兩種口徑，不能把共用 10 次對 18 個條件重複加總。

### 3. 付款敘述與實際流程不一致（文件可立即修）

`calibrate_one_condition` 預設 `settle_payment=True`。本次讀取 P5 reference_clean 與 P4 clean_patience2：summary 的 payment_status 均為 ok，payments.csv 分別有 25 與 14 列；payment_requests 卻均為 0。

因此正確說法是：P4/P5 執行既有模擬結算，0 額外查詢代表不需 payment fallback；P6 招募 benchmark 未執行分潤。沒有證據顯示真實金流付款。先前「本輪未分潤」的概括說法過強。

規劃：文件先校正；若新版實驗要禁止結算，新增明確開關與 not_run 狀態，重新做小型驗收。勿默默改舊結果。

### 4. 舊版品質分析尚未全部按可行解重整（立即可做，不必重訓）

舊 P5 分析目錄與報告仍保留既有口徑；新版分析器可以提供可行品質，但尚未交付一份明確取代舊診斷平均的舊結果再分析。P2 bootstrap 程式也沒有用 box feasibility 過濾配對。

規劃：保留舊輸出，在新分析目錄產出所有狀態、可行品質、雙方可行配對及失敗比例。舊版 formal CI 只代表當時設定，不能直接移植成新版受限求解優勢。

### 5. 正式統計與重現封存未完成（分析可立即做，執行需先凍結）

P2 已有 seed-level bootstrap，可抽出共用函式；P5 尚無正式 CI，P6 仍缺品質 IQR 等。應預先指定主要情境／比較與多重比較判讀，避免從很多情境選漂亮結果。

新版 P5 suite 已接受 --seeds，無須重新建整套 runner；主要缺口是分析與登錄。P6、受限 P4 runner 的 seeds 仍寫死 0–4，需要參數化。正式 seeds 100–129 已在舊 P2/P4 使用過；可稱與本輪 pilot 獨立，但不能稱為整個研究從未查看過的新 seeds。若要完全未見的確認集，登錄一組未使用的範圍。

規劃：來源快照、所有有效預設參數、套件版本、實驗 ID、seed 集、停止／失敗／配對規則一次封存；先在隔離目錄重播一個完整 seed，再啟動正式執行。

### 6. Evaluator coverage 已有基礎，可靠性研究仍有限（現在可做）

已有 test truth MSE、hard-region MSE、target±0.25 樣本數及 MSE；不是從零開始。23.2 是各 seed 樣本數平均，不能寫成某一次有小數筆資料。少於 30 是研究標記，未證明是可靠性門檻；稀疏也不等於已證明 OOD／外插。

規劃：從保存 artifacts 產生分區樣本數與誤差報告，列出 X 的局部支撐與 pooled/truth 衝突案例。若增加獨立診斷 grid，標明不是原 test split，不用它選每次交付 X。真實應用的外部驗證仍需另外取得資料。

### 7. 研究解釋與消融未完全交付（部分可立即做）

原計畫包含 α–q 對外部品質、品質隨 query 改變、典型／最差／最好／失敗案例及核心機制消融。原始 rounds 已提供部分材料，可先補圖與逐 seed 案例；跨版本不可混作同條件消融。P3 有負面證據，足以支持暫緩 pruning，但不代表完整方法的消融已完成。

### 8. P6 代理目標與 q 的部署主張仍待驗證（小型研究可行）

10 人、最多 3 人只有 10+45+120=175 個非空集合（預算篩選前），5 seeds 上限 875 次 coalition 倒推。可以共享固定模型與 proposals，做 pooled error 與 selection objective 排名相關、選擇後悔值及成本比較。這是離線診斷，不允許部署選人讀取 pooled 評分；所有集合相關的觀測以 seed 分群，不能當 875 個獨立樣本。

P3 若要恢復 pruning／新 q，先在受限版本重驗完整移除影響；有穩定證據後才設計更新。Shapley、分潤公平性與真實資料泛化目前不宜承諾完成。

## 建議執行順序與完成門檻

1. **先補研究可信度**：校正文稿、固定失敗 schema／配對規則、補成本計數。注入失敗的測試可完整產出報告。
2. **不重訓即可完成的分析**：舊 P2/P5 可行解重分析、target coverage、典型案例、P5/P6 統計彙總。每個結論有有效 n、失敗率和版本。
3. **新小型 pilot**：驗證新增計數與失敗流程，凍結環境與實驗設定；完整重播一個 seed。
4. **研究方向關卡**：A 維持主方法；決定正式 P5 主要情境與 D 對照範圍。P6 先做小型枚舉有效性驗證。
5. **最後才正式實驗**：使用事前登錄的確認 seeds；不以正式結果挑參數。不承諾正式實驗一定得到正向效果。
