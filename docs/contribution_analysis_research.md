## 1. 先回答三件事

### 目前候選點排除估計什麼？

它估計「在保留全部 local models、原 α 與成員身分時，拿掉某人的候選點，依既定求解程序重新產生解所造成的內部評分差」。這包括候選方向、求解路徑與預設起點變化的綜合影響。它不等於完整參與者移除。

令參與集合為 S、候選點為 I_i、固定 local model 為 f_i、目標為 t。搜尋目標是：

`L_opt,S(x) = Σ_i∈S α_i |f_i(x) − t|`，α 正規化且本輪靜態固定。

完整程序產生 X_full；只刪 I_i、保留所有 f 與 α 的程序產生 X_candidate,−i。固定的內部評分 L_eval 在 Clean 是所有成員誤差的平均；Controlled poison 是排序後兩端各去 floor(5×0.2)=1 個再平均。trimmed 是評分方式，該情境的搜尋目標仍是 uniform α 加權絕對誤差。

- `C_op,i = L_eval,S(X_candidate,−i) − L_eval,S(X_full)`。
- `C_candidate_pooled,i = E(X_candidate,−i) − E(X_full)`，其中 `E(x)=|f_pooled(x)−t|`。

這兩個 C 使用同一個候選排除解，只換評分者。C_op 的負號只表示內部評分在這個排除程序下改善。即使改用 pooled 評分，也沒有改變排除對象。

### 直接完整移除回答什麼？

同時刪除 I_i、f_i、α_i，對其餘成員設 `α'_j=α_j/(1−α_i)`，按固定倒推程序重求 X_full,−i：

`C_full,i = E(X_full,−i) − E(X_full)`。

它回答：「在固定已訓練模型、既定 coalition、target、box、權重規則、求解程序及起點規則下，若這次倒推沒有這位參與者，交付解的離線 pooled 品質會如何變化？」正值表示原參與有幫助，負值表示完整移除後 pooled 誤差較小。教學例：原誤差 0.02、移除後 0.05，C_full=+0.03。

它是參與者層級的**程序性離線反事實基準**。它不重訓 local models、不重做招募或用新人替補，也不消除該參與者在資料生成、既往訓練或 coalition 形成中的所有歷史影響。凍結 pooled evaluator 包含原研究資料，移除時不重訓它，以固定同一把尺；這把尺本身也不是無誤差真值。

完整移除會一起改變候選資訊、搜尋路徑、loss 成員與剩餘權重，不能將總差直接分解成純模型品質或純候選方向的因果效果。也不能跨不同 coalition、target 或 solver 當成固定個人屬性。C_full<0 與「移除後 pooled 誤差改善」是同一定義的兩種說法，不能互相當成獨立預測驗證。

### 正式負面結果之後，下一個具體問題是什麼？

優先問：「直接 full-removal 的正負方向與幅度，在固定反事實下，是否對有限求解預算穩定？」先確認研究基準的數值穩定性，再談如何低成本估計。P3 已否定目前候選排除的有效性主張，沒有回答直接完整移除基準對起點／預算的穩定性，也沒有證明 solver 是原負面結果的原因。

### 2.2 正式結果：未建立有效性

抽樣單位為 seed，每情境 n=30；Clean 每 seed 3 人，污染情境每 seed 5 人。240 人次不能視為 240 個獨立樣本。正式沒有缺 seed、失敗交付或不可行解，主要 Spearman 兩情境各有 30 個有效 seed。

| 原登錄指標 | Clean | Controlled poison |
|---|---:|---:|
| C_op 對 C_full 的 seed 平均 Spearman | 0.083，CI [−0.250, 0.400] | −0.047，CI [−0.290, 0.197] |
| 三分類方向一致率 | 40.0%，CI [27.8%, 52.2%] | 48.7%，CI [37.3%, 60.0%] |
| C_candidate_pooled 對 C_full 平均 Spearman | 0.004 | 0.050 |
| C_op 判負後完整移除改善 | 8/25，32.0% | 37/87，42.5% |
| pooled／truth 三分類方向不同 | 23/90 | 42/150 |
| 污染者完整移除改善 | 不適用 | 16/30，53.3% |

CI 是 98.75% Bonferroni simultaneous CI，seed bootstrap 10,000 次、固定 RNG 20261006。原成功要求兩情境都達到 Spearman≥0.5 且 CI 下界>0，以及方向一致率≥70% 且 CI 下界>50%；均未通過。原主 dead zone=1e-7；1e-6、1e-4 的敏感度結果未扭轉結論。

**未建立有效性：**目前 C_op 不能代表完整參與者貢獻；候選排除只換 pooled 評分也未建立有效性。這不證明所有未來估計器都無效，也不證明落差全部來自求解誤差、起點或模型成員改變。後三者尚未分離辨識。

### 從歷史程式確認的限制

1. `p3_contribution_validation.py:full_participant_removal` 暫時移除三種資訊並在 finally 還原。baseline 與每次完整移除都傳入完整候選平均 `fixed_start`。候選排除 `_compute_exclusion_reports` 沒有傳入 initial_solution，使用剩餘候選平均。因此原對照不是所有分支都從同一 X 出發。
2. `host_server.py:_solve_subspace_bfgs` 使用 `candidates.T @ beta`，beta 無非負或總和為 1 限制，是線性張成空間而非凸包。box 下實際 SLSQP，ftol=1e-9、maxiter=200；指定 X 起點先經最小平方映射，若映射後不可行再找可行 beta。一般情境不能保證映射前後 X 相同；本批資料殘差很小是額外核對所得。
3. custom 直接使用指定 X，按 anchors 方向前進，只檢查 box，不先投影到候選線性空間。若一般情境秩不足且起點在空間外，custom 的路徑不必等同 SLSQP 的候選線性空間。這是反事實求解域需明列的限制，不能默默修歷史程式後仍稱原方法。
4. best_of 按同一內部 optimization loss 選有限且可行的引擎輸出；沒有要求 `result.success=True`。custom 的 success 是「搜尋完成」，不是最優性證書。保存 CSV 只有被選引擎，缺逐引擎 success/message、迭代／停止原因、候選排除與 full 各自的完整軌跡。現有保存物不足以回推每個解是否收斂。
5. baseline 與移除解可能是不同局部解／搜尋品質；C_full 包含這種程序差異。不能因為正負明確或可重評，就稱其為精確最優解差。pooled/truth 衝突亦不能用 truth 篩掉後再宣稱 pooled 已有效。

上述限制是下一輪設計依據，不撤銷 P3 的既定負面結論，也不事後修補該結論。

### 5.1 研究對象與比較

只做 RQ1。估計對象保持為固定已訓練模型的倒推階段完整移除，不更動 α 規則、不重選 coalition、不重訓移除後模型。兩情境延用 P3 的選人規則、uniform static α、target=0、2D、box=[−1,1]，但用全新資料與模型。pooled 是獨立凍結研究評分器；truth 只在所有解產生後診斷。

每 seed/scenario 保存一次資料、local models、候選、coalition 和 evaluator；完整與每個移除子問題共用。比較兩個獨立求解的預算：

- A：歷史 best_of，custom 30、SLSQP ftol=1e-9/maxiter=200。
- B：只把 custom 上限改 120；SLSQP、annealing、目標、限制與起點均同 A。B 不用 A 的解 warm start，也不從 pooled 選引擎。這是「custom 預算敏感性」，不能稱全面提高所有 solver 精度。

每個設定都重求 baseline 及全部 full-removal，分別形成 `C_i^A=E(X_−i^A)−E(X_full^A)` 與 `C_i^B=E(X_−i^B)−E(X_full^B)`。不可固定舊 baseline 只重求移除解，否則混入比較不對稱。每個設定由其內部 L_opt 選引擎，評分後不得改交付解。

所有完整與移除呼叫傳入同一完整候選平均 X0。保存 SLSQP 的 beta0、實際 X0、投影殘差、rank／奇異值；custom 保存實際 X0。這輪只觀察原求解行為；若新資料發生投影殘差>1e-8、不可行映射或引擎搜尋域不一致，標記語義資格失敗並停止有效性主張，不改成另一種起點補救、不換 seed。需另立 RQ2 修訂後再驗證。

### 5.4 指標、驗收與停止條件

下列是**待確認的新設計值**，不是從 P3 重新挑出的成功線，也不是理論保證。target 尺度下將 `δ=1e-4` 作新研究主 neutral 閾值；`1e-7`、`1e-3` 只作敏感度。`τ=1e-3` 作可接受幅度差。這些值表達本輪可辨識與實質尺度，待使用者確認後才登錄；若應用要求更細差異，需先改設計。

每個 seed 定義 `a_s=mean_i[signδ(C_i^A)=signδ(C_i^B)]`、`b_s=mean_i[|C_i^A−C_i^B|≤τ]`，並報 max/median |ΔC|、兩邊 baseline 與移除解的 ΔE／ΔX。方向一致含 neutral；另報兩邊至少一方非 neutral 的配對一致率，及嚴格正負反轉數，防止大量 neutral 偽裝穩定。Spearman 僅次要，常數向量標 NA。

正式驗收順序：

1. **來源與流程**：預期 20 確認 scenarios／80 effects 全部存在；資格、求解失敗、超時、缺 artifact、undefined 各別列出，缺值不填零、不換 seed。所有被評解有限且 box violation≤1e-8；模型／evaluator hash 固定；重載 E 與保存值差≤1e-7；差值公式與剩餘 α 驗證。pooled 評分在解封前不能被 solver 讀取。未全部通過只交付失敗／不足結論。
2. **可重播**：pilot 重播 A 的 coalition／IDs／α／候選一致，X、內部 objective 及 pooled error 差≤1e-7；失敗先停，不把不可重現當成預算效果。
3. **有限範圍穩定性門檻**：兩情境各自 mean(a_s)≥90%、mean(b_s)≥90%。對兩情境×兩指標以 seed 為單位各做 10,000 bootstrap、RNG=20261016、98.75% Bonferroni CI，四個下界皆≥80%。不把成員當獨立樣本。
4. **方向識別充分度**：每情境至少 5/10 seeds 有兩邊至少一方非 neutral 的 effect，且這些非 neutral 配對方向一致率≥90%；否則即使整體 a_s 很高，也只能說差異多在 neutral，不能主張正負貢獻可靠。非 neutral 結果屬預先指定輔助資格檢查，不另作成功假說檢定。
5. **停止／結論**：任何完整性、語義或成本門檻失敗，停止擴大。穩定性未過即記「直接基準對此預算改動未建立穩定性」，先分析 solver／起點，再決定 RQ2。全通過只記「在這兩種預算與這兩個合成情境的有限樣本中，建立有限穩定性證據」；不等於全域最優、所有起點穩定或可部署刪人。

如 10 seeds 的 CI 太寬而未過，結論為證據不足，不能事後追加到顯著為止。若需擴大，另登錄全新確認批次與成本。只有進入下一階段且另獲確認後，才討論近似器；這輪不以同批結果選訊號公式。

## 12. custom模型方向作用累積：設計稿（2026-10-20）

依使用者要求，設計在custom實際合成方向時辨識各模型作用並跨步累積。完整設計：[custom模型方向作用累積](custom_direction_contribution_design_20261020.md)。本次只設計，未實作記錄器或跑新實驗。

主方法先以「模型i × 候選方向k」的原有secant／dynamic逐模型斜率拆出v_ikt，再按模型列加總成g_it，與原合成g_t對照。接受步沿用原步長s_t及原normalizer，分解delta_x_it=-s_t*g_it/norm(g_t)，投影到實際移動方向得到d_it；主輸出D_i=sum d_it，及S_i=D_i/總接受路徑長。這量測模型評分角色的signed方向推力，不是個人loss改善，也不把候選欄作用重複加分。

固定邊界：拒絕／切換完整記錄但不算已接受位移；強抵銷標數值敏感；無接受位移則S未定義；signed分數可大於1或小於0，不裁切。S總和為1，不是完整移除品質C的同語義signed分數，不能以零閾值判負貢獻，也不把S-C的MAE作主驗收。

參考需使用同一custom-only程序的baseline／完整移除；現有best_of的LOO不能直接改名使用。建議後續先4例技術／成本pilot及20個舊模型案例探索，合計最多244次custom求解、500,000輸入samples、300秒solver；來源與新結果另凍結。主要驗證團隊內與custom完整移除品質的排序關係。這是待執行設計與預算，不是已取得結果。

**已完成：**方法、解析公式核對、資料／成本／驗收與停止設計。**未建立有效性：**模型方向作用可反映LOO品質排序、0新增查詢與10%耗時目標。**下一步提案：**先建立不改求解行為的觀察器，通過機制重建驗收再小型探索；不自動修改alpha、pruning、付款、Shapley或Notion。
