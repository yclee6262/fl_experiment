# 初始 α 的低品質情境經濟敏感度：單次 B、三候選與五候選

## 使用範圍與口徑

本頁用同一批已完成的低品質情境 seeds 2400–2579，比較 Uniform A、Stage 0 品質權重 B、三候選 A+B+MSE power 1.5、原五候選的**交付 X 之 pooled 絕對 target 誤差**與**方法獨立 local-model API 請求量**。四種方法在每 seed 共用資料、local models、coalition、proposal 與 pooled evaluator；180／180 個交付都有效可行，研究用外部模型只在交付後評分。共同模型訓練、資格檢查、proposal 與外部評分未重複算進每個方法的請求量；真實部署的標記價格、網路延遲與每單位誤差的價值尚未知。一次批次 API 請求可能包含多個輸入樣本；若供應方按樣本而非按請求計價，必須改用保存的 `*_input_samples` 重新估算。

**證據分界：**本批事前登錄的主要比較只有「三候選對五候選」；其嚴格 pooled 品質改善門檻未通過。下列 A／B／三候選的增量比較及貨幣敏感度是**同批結果的事後分析**，不能轉為新的正式優勢。原始完整性及重評證據在 `alpha_weight_outputs/alpha_three_candidate_lowquality_formal_v1_20261004/`；重算程式和數字在 `analyze_alpha_economic_frontier.py`、`alpha_weight_outputs/alpha_lowquality_economic_frontier_v2_2400_180.json`。

## 如何代入實際成本

令 `v` 為每降低 **1 單位 pooled 絕對誤差**帶來的價值，`c` 為每次 local-model API 請求的成本，兩者均須用同一貨幣單位。只就這兩項定義平均效用 `U = -v × 平均 pooled 誤差 - c × 平均請求`。較昂貴方法 j 比較便宜方法 i 划算的**觀察均值**條件為：

`v × (E_i − E_j) > c × (R_j − R_i)`。

| 增加計算的決策 | 按本批平均值的損益平衡條件 | 解讀限制 |
|---|---|---|
| B → 三候選 | `c/v < 2.13 × 10^-6`；或每降低 0.001 誤差的價值高於約 **469 次** API 請求成本 | 誤差收益為本批事後比較，需獨立驗證。 |
| 三候選 → 五候選 | `c/v < 1.81 × 10^-7`；或每降低 0.001 誤差的價值高於約 **5,521 次** API 請求成本 | 正式比較未證明誤差收益大於零，此點估計門檻不穩定。 |

依這批**觀察均值**，當 `c/v` 高於約 `2.13 × 10^-6`，B 的效用較高；介於約 `1.81 × 10^-7` 與 `2.13 × 10^-6`，三候選較高；低於約 `1.81 × 10^-7`，五候選較高。這只是帶入本批均值的敏感度圖，不是已定義的商業價格、更不是方法在新資料上的保證。若考慮失敗代價、極端退步或固定部署費用，邊界會改變。pooled 誤差是否可以直接換算成業務效用，也需要應用場域確認。

## 尾端風險與研究決策

方法數增加不保證每個 seed 都改善：B 相對 A 最大 pooled 退步約 `+0.058154`；三候選相對 B 約 `+0.036188`；五候選相對三候選約 `+0.034366`。三候選相對五候選則有 `+0.049296` 的最大退步。其原因之一是內部選解規則可能選中 pooled 較差的候選，即使候選池較大也不會自動修正排序。所有失敗及尾端案例均須與平均誤差分開報告。

現階段可確認**方法之間存在品質—請求量取捨**，卻尚無證據宣稱哪一種有真實貨幣淨收益。若使用者堅持「新初始 α 必須嚴格降低 pooled 誤差且成本不增加」，本批三候選與前述其他新方法均不符合；保留原五候選為高品質研究對照。若應用允許以品質換取成本，應先提供每次查詢價格、每 0.001 pooled 誤差的容忍或價值、以及可接受的尾端退步，再依此固定新的正式決策規則，不能從本批事後挑最有利的門檻。
