# 單次 Stage 0 品質權重 B：新集成目標下的事後品質—查詢量診斷

## 為何檢查

新集成目標的正式跨情境品質門檻未通過，但 Stage 3 查詢量在三個已測情境都有下降。若實際 local-model API 呼叫有價格，另一個可行方向是只用既有 `B_stage0` 初始 α 做**一次**新目標倒推，不執行五次候選求解和五候選選解。B 的權重仍由 Stage 0 blind-test MSE 的反比得到；它是**既有初始 α**，不是本研究發明的新權重公式。

本頁從三批**已看過的正式研究資料**抽出保存的 B 候選 X，事後與舊目標五候選交付、新目標五候選交付比較；三批每批 180 seeds。這是**方法設計資料，不是事前登錄的 B 優勢或非劣性檢定**。候選 pooled 評分已由凍結 evaluator 重載核對，但 B 作為「單次正式交付方法」仍須另立獨立驗證。完整重算數字在 `alpha_weight_outputs/alpha_ensemble_single_b_frontier_posthoc_20261005.json`，程式在 `analyze_ensemble_single_b_frontier.py`。

| 情境 | 單次 B pooled 平均誤差 | 舊五候選平均 | 新五候選平均 | `B−新五` 平均差 | B／新五 Stage 3 平均請求 | 請求節省 |
|---|---:|---:|---:|---:|---:|---:|
| 低品質 25% | 0.019869 | 0.018702 | 0.016495 | +0.003373 | 349.42／1,685.83 | 79.27% |
| 乾淨基本 | 0.014168 | 0.013640 | 0.012510 | +0.001658 | 344.38／1,693.27 | 79.66% |
| 樣本量不平衡 4× | 0.015115 | 0.015442 | 0.013905 | +0.001210 | 314.35／1,623.67 | 80.64% |

三情境的 `B−新五` 描述性 95% 配對區間分別為 `[+0.001881,+0.004970]`、`[+0.000624,+0.002753]`、`[+0.000101,+0.002367]`。它們都指向**B 品質較差、查詢量較少**的取捨，不能說 B 的 pooled 品質優於新五候選。B 相對**舊**五候選的平均差依序為 `+0.001167、+0.000528、−0.000327`，描述性區間均跨零；跨零不證明 B 非劣。三批保存的 B 候選共 540／540 有效可行。

若只考慮 pooled 絕對誤差價值 `v`（每降低 1 單位誤差的貨幣價值）與每次模型呼叫成本 `c`，兩者同幣別，則單次 B 相對新五候選較划算的**本批觀察均值**條件是 `c/v > (E_B−E_5)/(R_5−R_B)`。依低品質、乾淨、不平衡順序，門檻約為 `2.52×10^-6、1.23×10^-6、0.92×10^-6`。這不是實際定價或未來資料上的保證；若供應方按輸入樣本計費，必須改用 `stage3_input_samples`，並計入標記、模型準備、選解、失敗與尾端品質損失。B 省去五候選選解的呼叫，表中僅比較 Stage 3，因此不會把節省誇大成整體系統比例。

**決策：**B 單次新目標是值得考慮的低查詢成本方案，但目前沒有證據說它品質更好，也沒有已定義的貨幣淨收益。若要提升為主要經濟方案，應先固定應用可接受的 pooled 品質損失或 `c/v`，再以未使用的 seeds 做事前登錄的品質／成本比較。若研究目標仍要求「新的初始 α 公式優於現有方法」，本診斷不算達成該目標。
