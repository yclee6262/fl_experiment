# 只保留兩位 Stage 0 權重的初始 α：開發結果

## 問題與方法

本試驗檢查能否在不取得新標記的情況下，以較少的 local-model API 請求完成單次倒推。對固定三人 coalition，取 Stage 0 blind-test MSE 最低的兩人；這兩人的既有反 MSE 權重 B 重新正規化，第三人 α 設為 0。Stage 2 的三個 proposal 和候選子空間仍保留；Stage 3 使用 `|Σ_i α_i f_i(X)−T|`，並略過 α 為 0 的 engine API 呼叫。這是**稀疏初始 α 和查詢策略**，不是移除參與者、重新招募或完整貢獻估計。

比較對照為同 seed、相同已保存資料、模型、proposals 和凍結 pooled evaluator 下的單次既有 B 與新目標五候選。pooled evaluator 只在 X 交付後評分。使用先前已作開發的低品質 25% 情境 seeds 2600–2629；前 5 筆為流程 pilot，後 25 筆為另一開發批次，**均非獨立正式檢定**。本方法沒有新增可信標記；成本欄位目前計入 Stage 3 local-model API 請求，未換算實際貨幣或延遲。

## 品質與成本

品質差定義為「稀疏法 − 對照」pooled 絕對誤差；負值才代表稀疏法較好。兩批 30／30 個交付 X 為有效 box 可行解；稀疏法的零權重 agent Stage 3 請求數為零，逐 seed 請求加總與獨立計數器相符。描述性區間對 seed 做 10,000 次配對 bootstrap；已看過的開發資料不能作正式優勢宣稱。

| 開發批次 | n | 對單次 B 的平均品質差 | 描述性 95% 區間 | 稀疏法較好／較差 | 平均 Stage 3 請求：稀疏／B |
|---|---:|---:|---:|---:|---:|
| Pilot 2600–2604 | 5 | −0.002617 | [−0.008032, +0.001615] | 3／2 | 229.20／393.00 |
| 後續 2605–2629 | 25 | +0.002330 | [+0.000185, +0.004649] | 10／15 | 234.64／315.24 |
| 合看 30 筆，僅供描述 | 30 | +0.001505 | [−0.000576, +0.003700] | 13／17 | 233.73／328.20 |

合看時稀疏法 pooled 平均誤差為 **0.020110**，B 為 **0.018605**，新五候選為 **0.014057**。稀疏法相對新五候選的平均差為 **+0.006053**，描述性 95% 區間約 [−0.000387, +0.016000]，30 筆中 10 筆改善、20 筆惡化。相對 B 的最差退步為 **+0.017935**（seed 2622）。稀疏法平均 Stage 3 請求比 B 少 **28.8%**，比新五候選的 1,723.80 少 **86.4%**；這些百分比不代表端到端時間或金額節省。

## 判讀與下一步

前 5 筆的品質方向未在後 25 筆重現；目前不能主張此法改善 pooled 品質，也不應為這個固定公式直接消耗新的正式 seeds。它提供了明確的**品質與 API 請求量取捨**：只有在可接受的品質退步、尾端風險與每次呼叫價格事前定義後，才適合作經濟方案比較。若目標仍是同時提升 pooled 品質並降低成本，下一步較有價值的是事前定義的**選擇性增算**：先交付 B 候選，僅在不依賴 pooled 評分的內部風險訊號觸發時，再求解額外 α 候選；需把觸發率、品質、失敗率與總成本一起配對評估。
