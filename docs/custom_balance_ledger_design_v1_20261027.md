# Custom 抵銷／制衡紀錄擴充：執行前設計 v1

日期2026-10-27。依使用者「依設計去做實作，並整理目前完整新做法」授權。這是前述制衡紀錄提案的具體化；不改既有A/E公式或原搜尋。新分量版本 custom_balance_ledger_v1，完整方法稱 custom_realized_gain_with_balance_v1。

## 定義

對每個有效方向輪，先按固定owner合併錨點的有號投影p_ot，定義 b_ot=max(-p_ot,0)/Σ_o|p_ot|。分母為0或原g_norm<=1e-8時b為null；不補0、不加epsilon。投影正負用嚴格符號；另報|p|<=1e-10的展示診斷，該門檻不改b或A。owner合併在取正部或負部前完成，不將同owner內相消再當成外部制衡。

b表示相對於本輪所有owner投影總幅度的抵銷強度，無金額、無loss改善單位，不跨輪直接相加作貢獻。全程主報：有效方向輪數、負投影輪數／有效輪數、每有效輪平均b（未反向輪含b=0）、負投影輪條件平均b。零方向輪另列，不進比例分母。分母、覆蓋率與資料缺失分開。

輸出按固定owner及輪提供上下文：首試接受、縮步後接受、全試走拒絕、零方向；另列模式切換、停止、有拒絕trial、box限制首次試走等可重疊標記。縮步指原試走attempt>0後接受，不把第一次box裁短當退火。停止含預算耗盡且可能同輪接受；必須明說標記重疊，不能相加當互斥頻率。

這些都是共現紀錄，不是錨點導致縮步、轉向或停止的證據。不估移除方向、不計新反事實、不新增評分或模型推論。沒有「已驗證保護收益」，該欄狀態一律 not_established，不用0表示已證明無效。

## 實作及來源

新增ledger.py、verify_balance.py、run_balance.py及tests_balance/，維持原accounting.py/observer.py不變。利用已封存兩案pilot之manifest、queries/evaluations/iterations及diagnostics補算。先核對舊completion_receipt全部列檔hash，再重算原A/E/P，要求新重算與舊原始分數完全相同；原獨立驗證器從原始回覆重建並重播未插樁solver。

新驗證器另以math.fsum從原始回覆建立方向分量及owner投影，獨立計算b、頻率、情境標記與彙總；不匯入ledger計算函式。舊驗證器可驗證既有A/E/P，但不能當成新b已驗證。

輸出另建 custom_balance_ledger_analysis_v1_20261027/，存在即停止，不覆蓋舊pilot、receipt或設計。輸出包含來源與設計快照、輸入hash、登錄、測試、逐輪新帳、owner摘要、完整帳目連結、重算一致性、獨立驗證、耗時與來源封存。不是新資料正式確認，不重新估計上輪29.3%/26.9%的搜尋耗時。

## 必要測試與停止

手算p=[3,1,-1]時b=[0,0,1/5]；同owner正負先合併；同向抵銷經正規化後方向可不變；正交投影0；有效非反向輪b=0；零方向b=null；反向頻率及平均分母正確；拒絕／模式切換／停止標記重疊；first box clipping不是退火；重複輪、錯shape、非有限值與缺紀錄拒絕；無有效輪的彙總為null；固定投影正比例縮放b不變；來源不變；A/E完全不變。

任一來源漂移、A/E差異或獨立驗證不符即停，不調符號、權重、門檻或挑案例。完成只代表紀錄可重現；不建立經濟有效性、公平或保護效果。只跑既有兩案離線資料及必要合成測試，pooled/truth/LOO/新訓練/付款/alpha更新皆不進入。
