# 求解過程梯度作用與完整移除：2026-10-18實驗結果

## 結論

**已完成實作與小型實驗，但本版本不適合作為LOO／完整移除效果的替代分數。** 不依賴歷史貢獻標籤的形式目標達成；本機批次計算成本達標；排序、方向、負值辨識與原始幅度落差均未達探索門檻，依固定規則停止。

更重要的發現是定義限制：沿既定路徑計算每人目標的改善，主要在分帳「誰的目標被改善」，未必能識別「誰讓團隊交付品質變好」。梯度寫法本身不能消除這個差異。我先前提出此方向時的「提供作用」說法需要以本輪精確定義收斂，不能解讀成已辨識造成更新的參與者。

本結果來自**40個既有seed、80條完整團隊軌跡、320個參與者效果**；沒有新獨立確認、沒有新LOO、沒有用LOO訓練或校準公式。不回填P3或其他正式結果。

## 這次如何算：初學者說明

正常解題會從起點走到最後的解。我們在每一步估計每個模型的局部坡度，再看實際移動有沒有沿著降低該模型誤差的方向走；把各步作用加總，得到每人分數。

例如實際往右走，甲模型的目標誤差往右會下降，甲得到正分；乙模型的誤差往右上升，乙得到負分。但這還不能證明甲造成了往右移動，也不能證明「沒有甲」之後解會更差。可能是別人的資訊讓甲一起受益。

設已接受路徑為x_0,...,x_T，個人目標為 `ell_i(x)=|f_i(x)-target|`，本輪主方法固定：

`A_i = -alpha_i * sum_t grad ell_i(x_t) dot (x_(t+1)-x_t)`。

現有對外API沒有梯度，故在各步起點附近、每維用h=0.001的正負鄰點做有限差分；遇box邊界裁切，用實際模型可見float32距離作分母。各人全部鄰點一次batch查詢。沒有讀模型權重求導、沒有改solver或alpha，也沒有pooled／truth參與配分。

比較參考仍是 `C_full,i = E_pooled(X_without_i)-E_pooled(X_full)`：正值代表原參與有助於該次離線pooled品質，負值代表完整移除後pooled誤差較小。它是固定前置模型與求解程序的反事實參考，不是無誤差的個人真值。

## 主方法與LOO差多少

| 指標 | Clean（120 effects） | 污染（200 effects） |
|---|---:|---:|
| 與LOO排序相關Spearman | -0.0145 | 0.0637 |
| 同一團隊內排序相關中位數 | -0.500 | -0.050 |
| 正負／近零方向一致率 | 54.2% | 56.0% |
| 參考負值中被找出的比例 | 4.5%（2/44） | 2.6%（2/77） |
| 預測負值的precision | 50.0%（2/4） | 66.7%（2/3） |
| 未校準分數對LOO的MAE | 0.100827 | 0.136176 |
| 全給0的MAE | 0.008065 | 0.010053 |

排序相關接近0，表示分數高低沒有穩定對應LOO效果高低；同團隊內也未改善，並非只被不同題目尺度混合掩蓋。兩情境各40個團隊內相關均可計算。負值precision的分母很小，不能因污染precision較高而忽略大量漏判。

MAE是將原始A直接當作C時的數值落差；二者定義不同，沒有理由預設同尺度或無偏。本輪事先禁止用LOO校正尺度。即便先不看幅度，排序及正負結果仍不足以支持替代LOO。

以seed為單位、10,000次bootstrap的方向一致率探索性95%區間：Clean為[45.0%,63.3%]，污染為[46.0%,66.0%]。這些是重用資料的探索區間，不是正式獨立確認或泛化保證。

## 兩個問題分開看：數值近似與貢獻定義

**第一，起點梯度不能可靠代表整個較長步驟。** 模型使用ReLU，目標使用abs，移動中可跨越折點。80案的「梯度分數總和－實際內部loss改善」絕對差中位數0.054286，最大3.924543。本輪A不是精確的改善分解，不能宣稱它具有總量守恆性。

**第二，把路徑積分做準，也不會自動變成完整移除效果。** 對這類連續分段線性loss，精確線積分會相消成：

`B_i = alpha_i * (ell_i(x_0)-ell_i(x_T))`。

這個事前固定的端點診斷只需要既有回覆，不需要梯度。它排除了本輪左端梯度積分的誤差，但仍是「個人目標改善分帳」，沒有反事實移除資訊。

| 精確端點分帳B與LOO比較 | Clean | 污染 |
|---|---:|---:|
| Spearman | -0.0461 | -0.1357 |
| 方向一致率 | 50.0% | 52.5% |
| 負值recall | 4.5%（2/44） | 3.9%（3/77） |
| 未校準MAE | 0.048334 | 0.042531 |

所以本輪負面結果不能只歸因於有限差分精度。這也不等於否定所有「過程貢獻」定義：其他直接分解更新生成機制的方法不在本輪驗證範圍。

## 成本與技術驗收

4個舊pilot案例各2次warmup、15組交替control／增強計算，共128次正常baseline求解。原X、loss及baseline calls核對通過；記錄器和分數不影響交付解。

| pilot案例 | 增強／正常耗時比 | 額外API calls | 額外輸入樣本 | 正常輸入樣本 |
|---|---:|---:|---:|---:|
| Clean／2026101600 | 1.0622 | 3 | 72 | 375 |
| Clean／2026101601 | 1.0570 | 3 | 84 | 456 |
| 污染／2026101600 | 1.0462 | 5 | 140 | 790 |
| 污染／2026101601 | 1.0666 | 5 | 140 | 395 |

四案中位數加總的耗時比1.055621，即**約5.56%額外耗時**，符合本輪10%目標；但新增樣本合計436，相對四案baseline2016個樣本多21.6%。成本不是零。batch把每人多個位置合成一次呼叫，不能把低API呼叫數解釋成只有少量模型工作。

80案既有軌跡配分另增加320次batch API呼叫、16,176個輸入樣本，相對原80案baseline60,103樣本多26.9%；配分實測0.0362秒、模型載入另計0.7017秒，未重跑這80個solver。計時為本機CPU、單執行緒、2D、m=3／5，不包含磁碟保存、網路／遠端batch限制；不能宣稱真實服務普遍只有5.56%開銷。成本隨維度、路徑長度及人數增加。

本次所有新工作合計：128次正常求解、65,072 API calls、87,228輸入樣本（含pilot及80案配分）；新增LOO求解0、重訓0。6個單元測試涵蓋線性解析結果、反向作用、邊界差分、無移動不查詢、abs折點及缺失資料失敗。獨立驗收程序從保存的API回覆重建全部320分數、核對端點恆等式、原始標籤配對、主要指標、查詢數與hash，結果通過。它證明記錄與計算可重建，不證明方法有效。

## 狀態與後續

**已完成：**固定公式／成本／停止條件登錄、黑箱梯度實作、6項測試、配分鎖定後才讀LOO、技術與成本pilot、320筆LOO比較、端點診斷、獨立重算、代表案例與圖表。

**未建立有效性：**本輪A可替代完整移除效果，或可準確代表誰造成了團隊品質改善。沒有新場景獨立確認；也沒有老師新comment或認可。`gate.json`為`exploratory_screen_not_passed`。

**下一步提案：**若繼續過程分解，需先從實際更新生成機制定義「誰產生了哪個更新分量」，再決定能否與完整移除品質建立關係；不能只把個人誤差下降換名為貢獻。本輪不自動換分數、改h、取反號、補樣本或推進另一條路線。

沒有alpha初始化／選擇／更新、pruning、付款、Shapley、Notion或商模工作。原P3、前兩輪結果及凍結來源均保留。
