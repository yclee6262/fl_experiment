# 低成本貢獻搜尋：開發、驗證與停止規則

執行結果（2026-10-20）：完成開發搜尋與兩次不同方法的獨立確認，最後排名點估計達標；樣本成本門檻過、本機時間門檻未過。詳見 [完整報告](contribution_rank_search_results_20261020.md)。以下保留原計畫，凍結版本另存各實驗目錄。

2026-10-20；依使用者新目標執行，目標為與完整參與者 LOO 品質貢獻的平均團隊內 Spearman >0.5。這是研究目標，不能保證一定可達；不得把歷史資料上挑出的高相關當獨立證據。

## 固定對象與邊界

參考仍為同 custom30、原X0、完整參與者移除的 pooled 誤差差值。模型、候選、剩餘權重皆按完整移除規則。新估計器只能使用部署可得模型回覆；pooled只於估計器輸出／所有解鎖定後評估，不用來產生分數、選求解點或刪人。truth不用。不更新alpha，不做付款、pruning、Shapley或Notion。原程式與所有舊結果不改。

## 第一個新假說：共享回覆庫重選

單步累積只看當步；新方法直接問：少掉模型i後，同一正常搜尋已探索位置中，剩餘團隊最偏好的交付位置是否改變？

1. 正常custom的每個既有查詢位置保存全部模型回覆；本輪開發先重用保存軌跡中的位置及絕對誤差。這不需歷史訓練資料。
2. 每位參與者i排除自身候選位置，按剩餘模型及正規化原權重，在共同位置庫選最小誤差的位置z_i；相同誤差取固定庫順序最前者。這是有限位置庫代理，**不是**真正完整移除求解，不稱已移除所有歷史方向影響。
3. 以原完整團隊可得的固定品質代理Q計算 score_i=Q(z_i)-Q(X_full)。預先固定四種Q：平均絕對誤差、絕對誤差中位數、signed預測中位數的絕對值、signed預測平均數的絕對值。target=0。前兩種重用庫回覆；後兩種只在選定端點補查原團隊，不能讀pooled。
4. 四方法完整揭露；不翻正負、不按情境選不同公式。這不是Shapley，也沒有逐人從頭跑custom；仍作逐人向量化庫重選，成本需如實列出。

## 開發與驗收

開發：既有20團隊（10舊seed×2情境，80效果），全部已視為開發資料。四方法在分數鎖定前不得讀LOO labels。分數鎖定後比較完整LOO，逐情境算平均團隊內Spearman；seed bootstrap 10,000次、RNG20261020。完全同分或缺值留未定義，不填0；有效團隊覆蓋需>=90%。近乎無效果另以範圍1e-4揭露，不能事後丟掉不利案例。

四方法若兩情境點估計均>0.5，選兩情境較小相關最大的同一方法，平手選較少新samples者。開發未通過，不啟動此方法確認，保留負面結果並根據失敗機制另立新方法登錄。

確認：方法與參數先鎖定，再新建2026102200–2026102219二十個seed的兩情境，共40團隊，與開發模型、資料及pooled分開。每情境平均相關均>0.5且探索95%區間下界>0、有效覆蓋>=90%才算本輪品質達標。較強的下界>0.5另行報告，不與點估計達標混稱。新資料資格失敗全部記錄、不換seed補樣；失敗不能再調此方法後重用同批稱確認。排名是團隊內比較，不能把80人當80個獨立團隊。

成本：新增正常baseline及觀察器成本、估計器額外calls/samples/時間、完整LOO參考另列。低成本驗收為相同正常求解+估計器samples <= 相同正常求解+完整LOO的70%，且實測時間不更高；無新增模型查詢不等於零CPU或儲存成本。本輪第一階段預算20正常重放驗證、最多10,000新模型samples、300秒，不重訓。若第一方法開發通過，確認另登錄準備及求解預算後執行。

## 若失敗的後續方向（尚未實作）

第一方向：完整角色的一步／短程反事實，保留完整solver狀態，移除模型與錨點，避免只歸因候選欄；不能拿同位置重啟冒充狀態續跑。

第二方向：共享查詢建立本次任務的回應代理，保留模型分別的預測，模擬角色變動後路徑。這不使用歷史資料，但若仍逐人模擬移除，就必須明示是低查詢的LOO近似而非嚴格非LOO；若需要pooled作線上配分則不採用。

本研究持續往目標前進，所有負面結果保留；不能單靠重複調整同一批分數宣稱找到可靠方法。
