# 當輪錨點 LOO 驗證：執行前規劃

本次依使用者授權執行。舊四 pilot、20 開發團隊，均為探索；不產生正式確認結果。沿用 `anchor_step_loo_current_design_20261020.md` 的 signed c 與 A，不改分數、alpha 或歷史 solver。

1. P0：重跑原11測試與獨立原始回覆 verifier，輸出寫入新研究目錄；驗證歷史來源及結果 hash。原始 loss／J 重建容差1e-10。
2. P1：報全部24條軌跡的接受、無接受、零方向、拒絕trial、模式、各人可比數、單步占比。固定原距離尺度1及0.5，兩邊均重算有效接受結果；尺度1重用舊回覆，尺度0.5新增查詢，不挑最佳尺度替換原方法。主尺度仍為1。描述淨分符號一致、全團隊排名及其有效分母；若兩情境任一平均排名<0.8或明確非零淨分符號保留<0.9，不能宣稱步長穩定。僅屬診斷門檻。
3. P2：只取每團隊第一個已接受步。沿原接受距離產生完整及逐錨點排除後的有效位置，之後全部恢復完整錨點。兩邊共用原步後 eta、模式、迭代索引等控制設定；變更位置的分支重算當前loss、重設該分支global-best為自身有效位置、以此重建history末端；不是全程永久移除。原程式經AST增加狀態輸入／紀錄，原計算語句維持順序；完整重跑必須符合原查詢數、序列hash、每迭代位置、分支及解。由第一接受步後續跑的完整分支也須重現原接續軌跡。零方向或dynamic失敗為terminal，停止後各時距沿用同一有效點，不填差值為零。
4. 同時保存立即（h=0）與續跑1、3、5次迭代。主指標是h=5對h=0符號保留／反轉（deadzone=1e-4），每團隊先算比例再平均；原c非零才進符號分母，後續進死區算消退、不是保留。報每組未定義團隊。單步及各h跨錨點range>1e-4且排名非全tie時算Spearman。各情境seed-bootstrap10000次、RNG20261020，95%探索區間；不同情境不合併個人當獨立樣本。
5. 延續支持規約：各情境至少8/10團隊有明確初始作用，h5團隊平均符號保留>=0.8且反轉<=0.1，並有至少8/10有效排名、平均rho>=0.5、95%區間下界>0。未通過就不支持直接累計為全程代理；不更改權重、符號、時距或追加seed。通過也僅限入口狀態，不證明全程累加。
6. P3：全部內部分數／分支點hash鎖定後才載入pooled。離線評估原全軌跡992組單步排除的有效點與原接受點，及短續跑各時距已產生點；比較signed差、死區符號、團隊排名。外部差直接用E(有效排除點)-E(完整點)，不以E接受或截零。不回填內部分數；truth完全不載入。
7. P4：記錄評分samples/calls、重播、短續跑、半步敏感性、pooled與獨立驗證各自成本、wall time與輸出大小。先四pilot確認技術、依最大每團隊每模型成本乘開發規模與4倍餘裕凍結預算；凍結前不跑開發。pilot總硬上限100000 samples/60秒模型操作，開發預算最多300000 samples/120秒；每一模型呼叫前檢查。全程保留失敗／缺失，不再開新確認集。

本輪不研究模型貢獻或報酬，不更新alpha、不pruning、不付款、不Shapley、不修改Notion。
