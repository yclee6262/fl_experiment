# 低成本貢獻度研究提案：過程統計校準

日期：2026-10-16（2026-10-17更新執行狀態）。本方法已按使用者授權執行：技術及成本通過，但開發效果未通過，未啟動新資料獨立確認。完整結果見 `docs/trajectory_calibration_results_20261017.md`。以下方法與門檻保留作事前設計紀錄。

固定入口：`docs/contribution_analysis_research.md`。本提案是後續研究假說，不回填P3或先前預算研究結果。α初始化／選擇仍暫停，不做α更新、pruning、付款、Shapley或Notion修改。

## 1. 推薦方向與初學者說明

推薦先研究「一次正常倒推的過程統計，能否預測參與者的Stage 3完整移除效果？」

做法像是先整理過去的解題紀錄及已知移除結果，學出最多四種情況的簡單規則表。以後遇到新題目，只看這次正常解題過程留下的資訊，就給出每人的效果估計，不再拿掉每人重算。

這是一個小型、可解釋的效果預測器，**不是已證明正確的貢獻公式**。離線研究階段仍需LOO標籤與獨立LOO驗證；省的是每次使用時逐人重新求解的成本，不是宣稱開發完全免費。

推薦小規則表而非立即指定某個加權公式，是因為目前沒有證據告訴我們「與大家一致」「候選點獨特」應各加幾分。先讓資料檢驗這些統計是否有預測資訊，避免把直覺當作貢獻定義。此選擇是本研究建議，不是老師指定或已同意的演算法。

## 2. 老師來源與估計對象

依恢復的自動轉錄，約42:16–43:09強調利用倒推過程statistics推導個別貢獻、避免逐人從頭重算。約36:55–40:43提醒不同排除範圍不是同一貢獻、過度近似可能偏離重要性。這是意旨整理；轉錄未重新聽錄且無可靠說話者分離。

本方法符合「利用過程統計、使用時不逐人重算」的形式目標；老師是否接受使用離線案例校準規則，仍未有確認來源，不能稱老師已認可。

估計對象維持：固定已訓練local models、coalition、target、box、權重規則與Stage 3程序，完整移除候選、模型與α後的外部品質差：

`C_full,i = E_pooled(X_without_i) − E_pooled(X_full)`。

這是倒推階段、固定前置狀態的程序效果，不是從訓練開始不存在的完整歷史貢獻，不等於Shapley。full-removal仍有求解、起點與評估器限制，是研究參考而非無誤差真值。

線上估計的目標是 `C_hat_i ≈ C_full,i`。正值代表預測其參與有助於本次pooled品質；負值代表預測移除後品質改善。保留signed分數與near-zero狀態，不轉成付款或刪人指令。

## 3. 一次正常倒推中記錄什麼？

固定第一版為現有best_of/custom30＋原SLSQP設定，不再做輪次比較。只用最終被選引擎的可行、已接受狀態序列：

`H = {x_0, x_1, …, x_T=X_full}`。

SLSQP使用實際callback狀態，custom使用接受步驟；保留引擎實際起點與原指定起點，不能混淆映射差異。最後交付解必須列入；只有真的不同且被接受的連續狀態才計一步。試探後被拒的點不混入主特徵，以免線搜尋次數主導統計。

對每個已被正常objective評估的x_t，保留所有成員既有回覆：

- `r_i,t=f_i(x_t)−target`：signed residual。
- `ell_i,t=abs(r_i,t)`：個別目標誤差。
- `L_t=Σ_j alpha_j ell_j,t`：當時的固定內部搜尋目標。

目前`host_server.py:_consensus_loss`每次計算目標本來就詢問所有成員，再聚合成L。新記錄器只能攔截這些既有回覆，不能為補特徵多問模型。若某狀態沒有完整既有回覆，標記資料不完整，不補查、不填零。需要先以記錄器測試確認callback／接受狀態可和既有API回覆對上，不能先宣稱零額外成本已完成。

候選點I_i、α與box是既有資訊。第一版α固定uniform，不把α大小當貢獻特徵；也不把先前初始化策略納入。

## 4. 第一版五個參與者統計與三個情境統計

令 `s=1e-8 + mean_t mean_j ell_j,t`，`B=norm(upper−lower,2)>0`。

| 統計 | 固定定義 | 意義與限制 |
|---|---|---|
| z1 相對目標誤差 | `mean_t(ell_i,t−L_t)/s` | 此模型沿途要求的誤差水準與團隊目標差多少；不是模型真實品質或貢獻 |
| z2 沿途判斷差異 | `mean_t abs(r_i,t−median_j r_j,t)/s` | 模型與其他人的判斷有多不同；少數意見可能有價值，不預設越不同越差 |
| z3 個別誤差改變 | `(ell_i,0−ell_i,T)/s` | 此模型從起點到交付解的誤差改變；不能把自身滿意程度當參與效果 |
| z4 候選與實際位移關係 | `dot(I_i−x_0, X_full−x_0)/B^2` | 候選方向與這次實際移動的關係；只是可觀察幾何資訊，不直接稱貢獻 |
| z5 候選差異 | `min_j!=i norm(I_i−I_j,2)/B` | 候選是否與他人接近；獨特不等於有用，接近也不等於參與者可有可無 |

三個所有成員共用的情境統計為：參與人數m、最終`L_T/s`、總接受路徑長度`Σ_t norm(x_(t+1)−x_t,2)/B`。合計8個輸入，第一版先固定，不無限制掃描公式。x_0是被選引擎的實際起點，基準full-removal使用的原指定起點另存於manifest，不混成新反事實。

不輸入：agent ID、seed、污染標記、pooled預測、truth、移除後X或誤差、任何測試答案。ID與污染標記尤其不能讓規則靠辨識固定污染者編號作答。

z3會望文生義成「此人的貢獻」，但它其實只描述自己的loss改變；把每步loss下降加總也只會得到相同端點差，並未解決歸因。z4、z5同樣只作候選幾何特徵，不能直接當參與者貢獻。

這些特徵是待檢驗的假說；不預設全部有用，也不預設輸入越大C就越正或越負。

## 5. 具體演算法：最多四葉的統計校準樹

### 5.1 離線開發一次

既有案例中，每位參與者建立一筆 `(z_i, C_full,i)`，z只來自正常完整團隊的倒推；標籤才使用已保存的完整移除結果。

用最大深度2、最多4個葉節點的回歸樹作規則表。每次只比較一項特徵是否超過門檻，不需要神經網路、Hessian、影響函數或預設線性關係。

完全指定的第一版擬合規則：

1. 根節點先輸出訓練標籤的加權平均。
2. 在每一節點，枚舉8個特徵的訓練相鄰不同值中點，找加權平方誤差下降最大的切分。
3. 只有兩個子節點各包含至少5個不同訓練seed時才允許切分；沒有正改善就保留葉節點。不夠資料不強迫長出四葉。
4. 相同改善時按特徵序號、門檻值由小到大決定，避免不必要隨機性。
5. 第一版資料同seed有兩情境，每個人次權重為`w=1/(2m)`，使每個seed總權重相同、兩情境各占一半。

對葉節點R_l，儲存：

`mu_l = Σ_(r in training leaf l) w_r C_full,r / Σ_(r in training leaf l) w_r`。

這是標準回歸樹的葉平均概念，加上本研究指定的seed支持量限制；不是聲稱套件原生就提供這個群組葉限制。

### 5.2 使用時的計算公式

固定訓練好的門檻與葉平均，對每人計算：

`C_hat_i = Σ_l 1[z_i in R_l] mu_l`。

白話就是：「這次他的過程統計落在哪一種已校準的情況，就輸出該類案例的參考效果。」正負及near-zero皆可能輸出，沒有強迫每人正值或所有人加總為1。

教學例：某一葉節點過去五個不同seed的等權效果為+0.010、+0.020、0、+0.015、+0.005，平均+0.010。新案例落入此葉就預測+0.010。這是公式示例，不是現有實驗結果或已學出的規則。

輸出需附所走的至多兩條規則、葉節點不同seed數、開發資料誤差與模型版本。不把訓練葉標準差當成已校準的個別置信區間；第一版沒有個人機率保證。

### 5.3 使用時流程

```text
正常Stage 3只執行一次
  -> 從既有回覆與接受狀態累積統計
  -> 計算每人的8項輸入
  -> 通過固定規則表
  -> 輸出signed C_hat、near-zero分類、規則與適用範圍
```

沒有逐人移除模型或候選；沒有為每人再呼叫solver；沒有即時pooled；不改α、不刪人、不付款。這裡LOO只存在於離線標籤及驗證端。

## 6. 為何合理、哪些地方仍不保證？

- 模型沿途回覆與候選幾何都被納入輸入空間，沒有先把參與者縮成單一候選支持度。是否兩組資訊真的都需要，要靠消融檢驗，不能因為放入特徵就說已處理完整作用。
- 對應的標籤直接是完整參與者移除效果，不以α大小、個人MSE、loss下降或共識程度替代定義。
- 規則很小，能檢查它實際依賴哪些統計；複雜度先受限制，避免用小資料任意配公式。
- 不做「模型越不同就越有害」的硬編碼，讓少數意見的效益由資料檢驗。

**最大的限制是資訊不足的可能性。** 一條正常軌跡沒有觀察到所有移除後可能走到的區域；不能由沿途統計直接保證還原完整反事實。相同統計也可能對應不同移除結果。這套方法是受限分布下的經驗預測，不是因果分解或精確full-removal恆等式。

如果簡單規則無法預測，應保留「這批統計與此模型不足」的結果，不立刻增加複雜度到能擬合、也不把分數改名為另一種貢獻來宣稱成功。老師是否接受這種離線校準形式，和它實驗是否有效，是兩個獨立問題。

## 7. 資料與最小驗證設計

### 7.1 開發資料

本次核對：原P3正式240 effects，30 seeds×兩情境；新預算研究確認組80 effects，10個另行seed×兩情境。合計320 effects、40個seed群組。兩個來源的runner／模型／資料及起點版本須先核對才合併；只取新研究A，不能把A/B當兩倍獨立樣本。

這些結果已被看過，全數視為開發資料。原P3正式負面結果不改；將舊標籤用於新開發，不會使其變成新方法的獨立確認。

現有輸出沒有完整保存每個已接受狀態的逐模型回覆，**不能只讀現有CSV就宣稱能建立這組特徵**。需先新增獨立記錄器，在舊保存模型上只重播正常baseline；確認X、loss、評分與舊baseline一致後，才配對既有C_full。此步最多80個baseline重播，不重訓、不重做逐人full-removal。若來源無法精確重播，該案例保留失敗，不能錯配標籤。

開發使用5折seed分組驗證：同seed的兩情境、所有參與者與任何重播都在同一折。每折只用訓練seed擬合門檻及葉平均，不用開發驗證折調前處理。深度、特徵清單先固定；若要換方法，另開版本，不沿用同一批開發評分冒充獨立驗證。

### 7.2 比較方法

| 方法 | 用途 |
|---|---|
| 固定預測0 | 檢查是否只在near-zero問題看起來有效 |
| 按m分組的訓練平均C | 零個人資訊基準；檢查是否只學到三人／五人情境的平均差 |
| 模型統計＋共同情境的同深度規則樹 | 消融：是否只靠模型反應即可預測 |
| 候選統計＋共同情境的同深度規則樹 | 消融：是否退化為候選幾何分數 |
| 推薦的完整8項輸入規則樹 | 唯一主要新方法，驗證前凍結，不以確認組改選消融勝者 |

所有基準和消融用相同訓練seed、權重、葉支持量限制。原C_op有效性負面結果作研究背景；不為這一輪再增加候選排除重算，避免把新問題又變成舊方法重跑。

### 7.3 技術pilot與獨立確認

先從舊pilot保存物各取兩情境作記錄器技術驗收，不作有效性證據。驗收內容：攔截前後API calls與輸入樣本完全相同；完整X、objective與重載品質差≤1e-7；可行容差1e-8；無pooled／truth輸入；逐模型回覆與接受狀態配對完整。不可為補特徵偷偷多查模型。

規則與登錄凍結後，以**20個全新、未用於任何調整的seed，分兩批各10個，兩情境共40 scenarios／160 effects**作確認。種子在正式登錄時查重並一次固定，不能依效果換seed。新資料每scenario只訓練一次local models與凍結evaluator。

每個確認scenario做一次有記錄器的正常baseline，立即產生所有C_hat並鎖定；之後才另外產生完整移除參考與pooled分數。兩情境每seed共10次baseline／full-removal求解，20seeds共200次，均固定custom30。不再測30／120。這200次是離線驗證成本，不算成部署貢獻計算的必要工作。

### 7.4 提案驗收條件

下列是建議的新門檻，不是老師指定或已確認結果；正式實作前需寫入登錄，之後不依確認結果調整。

1. **完整性與來源**：40個確認scenarios／160 effects預期鍵完整，無替換；資格／solver／記錄失敗與缺值保留，不填0、不把不可預測者當neutral。不完整不得作整體有效性主張。
2. **方向**：δ=1e-4、敏感度1e-7／1e-3。每情境以seed平均三分類一致率≥70%，98.75% simultaneous seed bootstrap CI下界>50%。
3. **幅度**：對按m分組的訓練平均C基準，每情境的seed平均MAE至少降低10%，且配對`MAE_baseline−MAE_new`的98.75%CI下界>0。兩情境×方向／MAE共四主要指標，10,000次bootstrap，RNG於登錄固定。0基準同時報告，不挑較弱者作主比較。
4. **負值不被多數類掩蓋**：每情境參考負值至少10個、分布至少5個seed；負值預測precision及recall均≥70%。不足時記負向辨識證據不足，不能只靠整體方向率宣稱可辨識負貢獻。兩批各自列結果；任一批方向點估計<70%，即便合併過線也不宣稱穩定有效。
5. **同資訊比較**：完整輸入若未優於模型／候選單組消融，不能宣稱兩組作用都已被辨識。Spearman、各類混淆、幅度誤差及pooled/truth衝突作輔助報告，不取代主門檻。
6. **成本**：線上額外model API calls／input samples均為0，沒有額外solver；記錄＋統計＋預測開銷目標≤正常Stage 3耗時的10%，並比「同一正常baseline＋全部full-removal」節省至少50% model calls。全部按相同工作範圍計算；若不達標就不能稱達到本輪低成本目標。
7. **停止**：記錄器改變X／calls、需要補查模型、開發分組驗證未顯示比常數基準改善、資料不足或成本超標，先停止並交付結果。不因簡單樹失敗就自動改深樹／神經網路；確認失敗不追加seed到過線為止。

額外訓練成本、舊baseline重播、全新資料／evaluator準備、離線full-removal標籤與驗收成本均另列。正式硬預算在實作前按pilot實測設定；本文件不授權大型實驗。

## 8. 成本與可用範圍

若接受軌跡共有T+1點、m人、d維，既有逐模型回覆累積與中位數統計約`O(T m log m)`，候選最近距離`O(m^2 d)`，固定深度D=2的樹預測`O(mD)`。這些是本設計的本機計算量，不是API查詢；不能把O(m^2 d)隱藏為常數，也不能僅憑0查詢就宣稱耗時為0。

完整保存研究軌跡需O(Tm)回覆；部署時大部分統計可串流累積，候選幾何另存。先以目前m=3／5、2D、target0、uniform α與固定solver範圍驗證。其他維度、target、參與人數或α設定標記未驗證，不能默認泛化。

沒有估計器誤差保證、個人因果保證或隱私安全保證。若將來想用估計負值做決策，需另立決策驗證，本研究不自行接上pruning。
