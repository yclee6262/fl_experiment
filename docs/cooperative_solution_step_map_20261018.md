# 合作找解逐步拆解與貢獻觀測位置

日期：2026-10-18。依使用者要求先拆解流程、標示可能計算貢獻的位置。本文件為現行來源核對與研究定位，沒有啟動新實驗、改演算法或把任何局部作用認定為完整參與者品質貢獻。

## 先建立完整圖像

本研究的「合作」不是把大家的模型權重平均成一個新模型。每人保留自己的模型，提供候選解I_i及對被查詢位置x的預測f_i(x)，Host利用這些資訊搜尋共同的決策向量X。

同一位參與者有兩種直接角色：

1. **候選／方向提供者**：提供I_i，影響可搜尋的表示空間及custom引擎的方向。
2. **模型／評分提供者**：提供f_i(x)，影響所有位置的團隊搜尋目標L(x)，不只評自己的候選點。

不能把「候選點被使用」或「個人誤差下降」直接當成完整貢獻。前者可能有冗餘，後者可能只是受益。alpha是預先固定的使用權重，不是本輪已辨識的貢獻。

整體流程：固定任務與已選團隊 → 每人提出候選 → 建立起點／查詢模型 → 聚合搜尋目標 → 兩個引擎各自找解 → 依內部目標選擇有效解 → 交付X → 離線品質與LOO驗證。

一般入口`run_experiments.py`還含前置選人及後續pruning／付款。本貢獻研究使用獨立入口、保存的團隊及模型，只分析Stage 3；不把一般入口完整執行一次，也不推進其pruning／付款。這幾輪alpha固定uniform；不能因一般程式有MSE初始化就把它帶回本研究。

## 一、前置與共同資訊

標記：**★**為有明確局部機制、值得拆解的觀測位置；**△**為可觀察但不能單獨稱貢獻；**驗證**只在解已產生後使用。標記是研究機會，不是有效性證明。

| 步驟 | 實際操作與可取得資訊 | 可標示的作用／限制 |
|---|---|---|

| 1. 準備local models | 各人事先訓練f_i；研究載入已保存模型 | 本輪不估計資料或訓練歷史貢獻，不重訓 |
| 2. 資格／團隊與alpha固定 | 一般程式有盲測、反推資格、選人；本輪進入Stage 3時已固定 | △ MSE／資格／alpha不是合作找解貢獻；不在這輪改選人或alpha |
| 3. 產生候選I_i | Phase 2在各人的模型上反推輸入；方法D用平方誤差及Adam，再裁切box | ★ 候選提供了什麼新方向／可達位置？候選在自己模型上好，不保證團隊品質好 |

| 6. 聚合搜尋目標 | L(x)=sum_j alpha_j ell_j(x)，程式會正規化權重 | ★ 哪些模型評分影響位置間優劣、試探接受與引擎選擇？單看alpha_j ell_j只是目標組成，非邊際品質效果 |

## 二、custom引擎：每次迭代再拆成七步

| 步驟 | 現行custom真正做什麼 | 貢獻觀測機會 |
|---|---|---|
| C1. 建立候選方向 | 從目前x_t指向每個I_k；距離太小則跳過；方向單位化成u_k | ★ 候選k提供哪個幾何方向？與其他方向是否冗餘？這仍只是幾何描述 |
| C2. 估計方向斜率 | secant：比較L(I_k)與L(x_t)；dynamic：沿u_k試探一個有界小步，再比較團隊loss | ★ 哪個候選方向被判定有利／不利？哪些評分模型讓這個判斷改變？兩種角色開始交會 |
| C3. 合成方向 | 每方向產生v_k=方向權重a_k×斜率d_k×u_k，全部相加得g_t | **★最直接的更新來源觀測點**：各人的候選方向向量如何相加、互相抵銷或主導合成方向 |
| C4. 單位化及邊界限制 | 將g_t除以其norm，再依box限制步長；g過小就停止 | ★ 哪些分量受限制？△ 單位化造成交互作用，未單位化大小不能直接當最終位移比例 |
| C5. 試走／退火 | 沿-g_t試探，若L不下降就縮步，最多10次 | ★ 候選決定試走方向，所有模型回覆共同決定哪個步長被接受。被拒點也是判斷資訊，不應只留成功步 |
| C6. 接受或切換 | 下降則接受並記錄；secant失敗可切dynamic；dynamic再失敗則停 | ★ 哪些資訊促成接受、拒絕、切換或停止？這是決策作用，尚非最終品質貢獻 |
| C7. 更新最佳解並重複 | 保存已接受的最佳可行解；用它進入下輪 | △ 回看每人誤差改善只表示受益；須連結C1–C6才知道實際更新來源 |

程式依據：`host_server.py:412`至`:535`。這裡的g_t是程式用候選方向與割線／試探斜率合成的搜尋向量，**不等於**完整目標對x的真梯度；上一輪新增有限差分的個人梯度，也不是現行custom用來產生更新的原始分量。

### C2／C3可再拆成「誰提供方向 × 誰提供評分」

用k表示候選提供者，j表示模型評分者。令a_k是方向混合權重，alpha_j是評分權重；目前通常數值同源，但它們扮演不同角色，都保持固定。

secant時：

`u_k = (I_k-x_t)/norm(I_k-x_t)`

`d_k = [L(I_k)-L(x_t)]/norm(I_k-x_t)`

`v_(j,k) = a_k * alpha_j * [ell_j(I_k)-ell_j(x_t)]/norm(I_k-x_t) * u_k`

`g_t = sum_k sum_j v_(j,k)`。

dynamic時，把I_k替換成實際有界試探位置x_t+h_k u_k、分母換成h_k即可。所有分解都基於原本已查過的模型回覆；若只新增記錄，理論上不必增加模型查詢。但目前來源沒有把所有方向分量與逐模型試探回覆完整輸出，仍需新增記錄及核對，不能宣稱已實作完成。

這形成一張矩陣：每一欄是某人提供的候選方向，每一列是某人的評分模型。對欄加總得到候選方向角色；對列加總得到模型評分角色。**兩者是同一筆更新的兩種視角，不能相加計兩次總貢獻。** 矩陣也不是任意可加的個人品質分數。

若此輪最終接受的步長為s，且g_t非零，則實際位移為：

`delta_x = -s * g_t/norm(g_t)`。

採用共同的實際s及norm，可以建立一個局部的代數分解 `delta_x_(j,k)=-s*v_(j,k)/norm(g_t)`，其總和等於實際位移。它只證明沿**已發生決策**可拆出更新來源；移除某人會同時改變權重、方向、norm、步長與接受分支，因此這不是移除後位移，也不保證分解唯一或具有品質價值。

例：甲提供「向右」候選方向，但是否向右有利，是甲乙丙的模型共同評分決定。不能把整個向右步都記給甲，也不能因乙自己的誤差下降就說乙產生了向右更新。

## 三、另一引擎：SLSQP／BFGS的分工不同

| 步驟 | 實際做法 | 貢獻觀測機會 |
|---|---|---|
| B1. 候選參數化 | x=sum_k beta_k I_k；在beta上尋優 | ★ 候選提供表示空間。但beta並非機率／貢獻；程式沒有beta>=0或sum beta=1的simplex限制 |
| B2. 起點映射 | 指定X0時用least squares回推beta；box模式必要時找可行起點 | △ 需分開記錄名義X0與實際映射X0，避免把起點差異當貢獻 |
| B3. 試探、目標評估、更新 | box模式使用SLSQP，未約束舊模式使用BFGS；目標仍查所有f_j | ★ 模型評分角色仍存在，但內部更新由SciPy產生，不能套用custom的v_k公式 |
| B4. 回傳引擎解 | 返回x、loss、solver狀態及history | △ 若要分解更新來源，需取得引擎自身試探與限制資訊，不能用最終beta直接配分 |

程式依據：`host_server.py:351`。若候選線性相依，某個方向可能由多組beta表示；即使某人beta很大，其他人也可能替代其方向。同樣地，刪一個候選不一定縮小span，仍可能改變有限步求解行為。

## 四、合流、交付與離線驗證

| 步驟 | 實際操作 | 作用／邊界 |
|---|---|---|
| 7. 引擎選擇 | best_of比較兩引擎的有效解，以原L_opt較小者交付 | ★ 哪些模型評分促成選甲引擎而非乙引擎？這可能是離散切換，單一路徑分數看不到。不能用pooled替代此決策 |
| 8. 交付X | 保留最終選中的有效解及失敗狀態 | △ 某人的候選靠近X，不代表該人造成或提升了X；需連回生成過程 |
| 9. 離線品質檢驗 | 解鎖後使用固定pooled evaluator評已產生的X | **驗證**結果品質；pooled不產生方向、選引擎、改alpha或刪人。truth只作診斷 |
| 10. full-removal／LOO | 同時移除I_i、f_i、alpha_i，正規化剩餘alpha，用固定起點規則重新求解，再離線評分 | **驗證參考**：回答本次Stage 3若沒有此人的程序效果，包含前面多處互動；不是單一局部記錄能自動等價替代 |

程式的valid_delivery主要檢查有限loss及指定模式下的box可行性，不等於solver的success旗標或全域最優證明。引擎名稱bfgs在box模式實際為SLSQP。這些限制在研究中須保留，不用名稱或成功執行推論全域最優。

## 五、目前最值得標示的位置與記錄缺口

1. **custom C2–C3：實際合成方向。** 現行演算法已有各候選方向及斜率，最接近更新生成機制；進一步分開方向提供者／模型評分者。
2. **custom C5–C6：步長接受、拒絕與模式切換。** 評分資訊在此實際改變路徑，應保留被拒試探，不只接受狀態。
3. **best_of選擇：哪組模型評分使引擎勝出。** 這是兩引擎合流的離散決策，需要同時保存兩邊解及逐模型評分。
4. **候選空間及可行性。** 可檢查rank、冗餘及起點映射；它們是結構／可替代性描述，不能改稱候選支持度即貢獻。

現有80案軌跡保存了被選引擎的狀態、逐模型回覆及少量引擎資訊；沒有足夠完整的C2–C6決策記錄來事後精確重建每個更新來源。上一輪有限差分梯度資料也不能補回這些原始分支。若後續實作，需先新增不改行為的觀察記錄器並核對X／查詢一致，再決定評分方法；本文件沒有開始這項工作。

## 研究狀態

**已完成：**現行合作流程與兩引擎分支的來源核對，標示候選、評分、更新、接受及引擎選擇等觀測點；推導custom已發生更新的局部代數分解。

**未建立有效性：**任何上述局部作用可當完整參與者品質貢獻、可替代LOO，或可合併成唯一公平分數。過程分解的代數正確不等於反事實或外部品質正確。

**下一步提案：**若使用者後續決定繼續，先以custom C2–C6原始決策記錄為研究起點，固定「更新來源」與「品質貢獻」的不同驗收。本次只拆解與文件化，不跑新實驗、不修改歷史solver，也不推進alpha、pruning、付款、Shapley或Notion。
