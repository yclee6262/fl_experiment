# 目前錨點貢獻設計與待補驗證

日期：2026-10-20。範圍：當輪錨點 LOO，使用內部 loss。模型貢獻、基本保障與分潤暫不研究。本文件整理既有方法並收斂後續方向，沒有新實驗結果。

本文件取代上一份候選方法文件作為目前方向入口：不推進 ±10% 方向擾動方案；先沿用已存在的單步錨點排除方法，保留原正式與探索負面結果。

## 一、估計的是什麼

問題：在完整團隊原本走到的狀態，如果這一步沒有錨點 i 提供的方向，固定比較步長後，內部目標的改善會少多少或多多少？

名稱：**固定原軌跡、等距試走的單步錨點 LOO 增益**。

它是明確定義的局部反事實，不是全程參與者移除、不代表最佳解差異，也不是總改善的唯一分帳。

L(x)=Σ_j α_j |f_j(x)-y_target|，α 沿用原完整團隊並正規化；此處的模型與權重在兩個分支完全相同。現有實驗 target=0。pooled 不進入 L、分數或接受判斷；truth 不作計分。

## 二、逐步計算

對原搜尋一個已接受步 t：

1. 保存原位置 x_t、完整模型回覆、secant／dynamic 模式、原合成方向 g_t、錨點分量 v_it、原實際接受點 x_(t+1)。
2. 固定比較距離 s_t=||x_(t+1)-x_t||。原 solver 的步長會調整；這裡是固定該步已接受距離，不是全程固定步長。
3. 僅排除錨點方向，g_(-i,t)=(g_t-v_it)/(1-a_i)，a_i 是原錨點方向權重。模型 i 仍參與評分，模型權重 α 不變。
4. 若有可用剩餘方向，沿 -g_(-i,t)/||g_(-i,t)|| 走 s_t 得到 z_(-i,t)。不重新退火、不延續這個分支。
5. 若 L(z_(-i,t))<L(x_t)，替代分支接受 z；否則留在 x_t。
6. 計算 c_it=min{L(x_t),L(z_(-i,t))}-L(x_(t+1))。

剩餘方向低於原停止閾值時，以不移動計算；沒有剩餘錨點則未定義。等距試走超出 box，標記不可比較，不裁切、不縮步、不填零。缺失時保留局部明細，不把部分和冒稱完整累計。

例：原位置 loss=10、完整步後 loss=7；排除後 loss=9，c=+2；排除後 loss=6，c=-1；排除後試走 loss=11、拒絕留原位，c=10-7=+3。

正值代表在此等距比較中，保留錨點較有利；負值代表排除方向後該步較有利。零值只是這個比較沒有差異，不表示沒有所有形式的價值。

## 三、累計與輸出

A_i=Σ_(原軌跡已接受步 t) c_it。

保留正累計 A_i^+=Σ max(c_it,0)、負累計 A_i^-=Σ min(c_it,0)、淨值 A_i、逐步分數、可比較覆蓋、狀態與成本。不截除負分、不取絕對值、不額外乘改善量、不強迫各錨點分數加總為一。

不同錨點可以互補或重複，故 Σ_i c_it 不必等於當輪改善；跨步累計也可能重複反映相似作用。目前 A 只能稱「累積單步局部增益」，未證明是全程貢獻。

重要範圍修正：現有程式跳過沒有接受步的迭代。它不涵蓋「移除錨點後，本來停止／拒絕的迭代是否能改善」，也沒有分配拒絕或停止的資訊價值。沒有接受步時輸出不可用狀態，而不是所有人零貢獻。將來若要涵蓋所有迭代，必須另定試走距離與停止分支語義，不能暗中改進本版分數。

## 五、需要補的驗證：依序進行

### P0：語義與重建核對，先重用現有資料

先做來源／設定相容性檢查，避免重新實作同一方法。以獨立 verifier 核對方向移除、距離、回覆、接受結果及正負累計；原搜尋點與結果必須不變，pooled 不可被計分流程載入。

特別待補：現有 kernel 以 `case['alphas']` 的 w[k] 當移除時的方向權重，並對新回覆直接取 abs（target=0）。這與既有 uniform、target=0 實驗相容；推廣前必須明確保存 a 與 α 的對應，及使用實際 target。不能把目前測試通過外推為任意方向權重或 target 都已支援。歸一化係數雖通常不改單位方向，仍會影響近零方向的停止閾值判定。

驗收：完整來源與參數可追溯、原軌跡不變、獨立重建差≤1e-10，缺失／不可比較不得被填成零。失敗則先修技術問題，不解讀效果。歷史實作與結果不覆寫，後續修改另立版本。

### P1：接受步覆蓋、步長條件與穩定性

先用既有紀錄整理：接受／拒絕／停止比例、每人有效步數、近零與正負分布、是否由單一步主導、邊界與方向切換的分布。這是描述，不用來事後選時間權重。

固定原接受距離使比較明確，但它是完整團隊成功選出的距離，未必適合移除後方向。若要測試步長敏感性，另登錄少量固定尺度（例如原距離的 0.5、1 倍；兩個分支均重算相同距離與接受結果），只診斷正負／排名是否改變，不挑較好尺度替換主公式。拒絕迭代的新定義另案處理。

判讀：敏感或覆蓋不足時，只能報條件式局部增益，不能稱穩定、涵蓋每輪的錨點貢獻。具體穩定性容忍門檻須在執行新查詢前登錄，現階段不宣稱已通過。

### P2：累計假設——優先的新診斷

問題：單步差異會保留，還是被後續搜尋抵銷／反轉？

推薦先在四個舊 pilot 建立完整狀態重放，再固定 20 舊團隊，每條軌跡取第一個已接受步，僅作入口狀態診斷，不宣稱涵蓋中後段。從同一原狀態產生完整及單步排除後的有效位置；分支只在當步排除，後續恢復全部錨點。以明示一致的原步後控制狀態（eta、模式、迭代計數等），比較立即及續跑 1／3／5 次迭代的內部 L。

這刻意測量一次位置擾動的持續性，不等同「之後永遠移除錨點」。若要測永久移除，另列對照，不能混為同一結果。分支位置變更後，當前 loss 與位置依賴查詢須重新計算；固定錨點回覆只有確認有效時才可重用。

前置要求：完整分支不改位置時，狀態續跑必須重現原搜尋。單純用同一 X 重開 solver 會重設步長或模式，不算重放。

最多四 pilot 加 20 舊團隊，共 96 個錨點分支與 24 個可共享完整分支；每條最多續跑 5 次迭代。這是分支／迭代上限，不是模型查詢上限；退火可有多次試走。先由 pilot 實測每迭代成本，再凍結 samples、時間預算，未凍結前不啟動 20 團隊探索。

報每個時距的符號保留、差值幅度與團隊內排名，平坦或停止保留狀態；以 seed／團隊為單位估不確定性。若單步幫助經常反轉，停止將直接加總當成全程貢獻代理的推進，不靠加權救同一輪。若穩定也只支持繼續測多個位置與未見資料，不能據單一入口狀態宣稱累計成立。

### P3：外部品質，作獨立診斷

在局部分支與分數鎖定後，離線用 pooled 評估兩邊實際接受點，檢查內部 c 與外部差值是否同號、同排序。pooled 不決定分支是否接受，也不回填分數。

若不一致：內部局部增益的定義仍成立，但不能宣稱它衡量外部品質貢獻。這與「計算有沒有算對」是不同驗證。

### P4：成本與未見資料

分列 baseline、額外影子查詢、重播、快取、獨立驗證、pooled；同口徑比較輸入 samples、API calls、wall time 與儲存。不要用低 API batch 次數掩蓋模型工作量。

舊 20 團隊全部是開發／診斷資料。方法及累計主張有支持後，再另登錄未用模型／seed 的確認集、效果門檻與成本上限。不同函數、非零 target、非均勻權重、維度和人數是外推條件，不能只換 seed 就宣稱複雜場景成立。
