## 方法：用這次搜尋的回覆做模擬，再用這次資料評品質

可把它想成先畫兩種小地圖：一張近似「原模型會如何回答」，另一張近似「目前觀測顯示的品質」。前者模擬角色移除後搜尋，後者給交付解評分；兩者用途不同。

1. **記錄正常搜尋。** 原custom30照常產生X_full，順便記下已查位置與每個模型的signed回覆。原X0、box、target0與uniform alpha不改。
2. **補共同探測點。** 正常查詢的包圍盒外擴20%，先取5×5格點。再做3輪：由linear與RBF兩個插值器對代理搜尋位置的預測分歧，選最多12個新位置，讓原團隊所有模型共同回答。每團隊本次實際共增加61個位置，不用LOO品質或pooled選點。
3. **在代理上模擬移除。** 最終使用RBF近似每個原模型，在代理上逐人刪模型、錨點與alpha，剩餘權重正規化，由原X0執行原custom30。原模型不逐人從頭跑；但代理確實逐人模擬反事實，不能稱完全不含LOO。
4. **由當前資料提供品質摘要。** 取原模型池中既有Stage1驗證MSE最低的3個提供者。每位用自己距X_full最近128筆既有觀測，擬合局部二次回應曲面g_k。MSE只用來選固定評分者，沒有直接當個人貢獻，也不改求解alpha。研究程式模擬client本地計算；部署摘要API尚未建置。
5. **算固定端點品質差。** Q(x)=median_k |g_k(x)-target|，A_i=Q(z_proxy,-i)-Q(X_full)。正值表示原參與在這個代理品質尺下有幫助，負值表示代理移除後品質較好。所有A先鎖定，再讀LOO參考。

二次曲面的通用基底為[1,u1,u2,u1²,u1u2,u2²]，u=(x-X_full)/h，h為第128近觀測距離。Gaussian距離權重、ridge=1e-6×斜率Gram平均對角，intercept不懲罰。係數由本次**observed_y**估計，不讀clean_y、truth、pooled或歷史LOO標籤。Q使用原固定3人評分面板，不因假設移除的對象重建它。

RBF固定thin_plate_spline、degree1、nearest32、smoothing1e-10。共同探測與兩個插值器的分歧只處理搜尋代理，不以品質摘要修改原solver目標。SciPy參數語義見[官方RBFInterpolator文件](https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.RBFInterpolator.html)；文件不保證此研究方法有效。

## LOO基準與資料順序

本報告的LOO專指：固定已訓練模型、coalition、target、box與原X0，將某位參與者的模型、錨點及alpha一起排除，重新以**custom30**求解；C_LOO,i=E_pooled(X_actual_without_i)-E_pooled(X_full)。它是固定程序的倒推階段效果，不重訓模型、不重選coalition，也不是全域最優或整個訓練歷程價值。不能改稱已驗證best_of、custom120或其他起點程序。

資料與執行固定順序：

- 開發：原seeds2026101610–1619×兩情境，共20團隊，全部視為已用資料。
- 第一個固定linear9版本：先凍結再用新seeds2026102200–2219×兩情境確認；離線代理品質相關Clean0.418／污染0.730，Clean失敗。這批40團隊沒有再當最後方法的未見確認。
- 最後候選：開發Clean0.60／污染0.56後，先凍結單一版本，再建立新seeds2026102300–2319×兩情境40團隊；新建資料、20個local models與pooled。
- 最後確認依序完成全部資料、全部proxy解、全部A鎖定、全部真實LOO解，才讓pooled對正常解與真實LOO解作離線評分。pooled沒有進入A、求解、探測、alpha或刪人決策。truth只在另外的診斷分析使用。

兩個OpenMP技術錯誤都發生於資料／模型生成前，原失敗紀錄保留；按原seed與設定在修復版本重試，沒有換seed或排除低品質案例。全部40團隊完成，沒有資格失敗或事後補樣。

## 成本：省查詢，未省下本機總時間

| 相同40團隊的工作 | 模型輸入samples／scalar calls |
|---|---:|
| 正常求解，共同baseline | 16,889 |
| 新方法額外共同探測 | 9,760 |
| 完整LOO額外查詢 | 53,204 |
| 正常＋新方法 | **26,649** |
| 正常＋完整LOO | **70,093** |

計入共同baseline，新方法少**61.98%**；只看額外工作則少81.66%。相較只做正常求解，新方法仍多57.79%模型輸入，不能稱免費。模型輸入量≤完整LOO方案70%的門檻通過。

此外，每個任務3位提供者各掃描自己的500筆資料、選128筆擬合：40任務共掃描60,000筆、選取15,360筆，沒有新收集觀測。這些本次資料、局部擬合及摘要可得性是額外成本與假設。理想摘要可只回傳3×(6係數+1尺度)=21個浮點數，不含協定；本研究尚未實際建置或量測摘要傳輸與隱私機制。 另在480組端點×提供者的事後描述中，10組超出擬合鄰居半徑，最大距離/半徑1.61；全部保留，沒有靠刪除外插案例提升相關。

以事先固定的4案（2300、2301各兩情境），每方法2次warmup、10次輪替配對，計入模型載入、正常搜尋、共享探測／代理與client資料掃描擬合；完整LOO也重用已載入模型，沒有靠反覆重載模型放大對手成本。下表是4案各自中位數再加總，**不是全部40案端到端比例**：

| 方案 | 四案中位數加總 | 相對完整LOO |
|---|---:|---:|
| 完整LOO，重用模型 | 281.55 ms | 1.00 |
| 原始代理程式 | 1,155.11 ms | 4.10 |
| 鄰域快取與代理批次運算版 | 411.09 ms | **1.46** |

快取只處理數值計算，不更換代理、探測點或公式；20開發與40確認團隊重放的選點、RBF搜尋歷史及端點全一致，分數不變。**本機時間門檻仍失敗，因此不能宣稱這是一個全成本都更低的方案。** 快取依賴本次SciPy實作，換版本須重驗證。

若只作理想化串行API延遲分析，四案節省3,618次模型scalar calls，多出的CPU時間相當於每次約0.036ms；這只是忽略額外摘要協定、批次／平行化的成本情境推算，沒有實測遠端加速，不作採用證據。

當前確認含正常、探測、參考、獨立重放、計時與技術失敗warmup，以及共同資格檢查，共300,144個模型輸入評估，低於500,000上限；pooled離線點評估另400次。所有新開發、技術重複與兩次確認合計463,253個模型輸入評估，另有80個新情境的模型／資料準備；神經模型訓練、pooled訓練及client回歸不混成API樣本數。完整ledger另存。
