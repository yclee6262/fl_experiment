# 模型池換算後貢獻：單輪決策作用辨識驗證 v1

日期：2026-10-28。使用者授權依前一則五類情境設計實作及驗證。本文件與fixtures在新搜尋前封存；不依結果改公式、探測點或驗收線。

## 1. 問題與限制

檢查既有 C_norm=Σv_m[loss_m(x_minus)−loss_m(x_full)]/s_m 能否分辨模型評分使單輪決策改善、惡化或沒有作用。s_m=Q90−Q10，固定25點[-1,-.5,0,.5,1]²、線性分位數、正權重尺度須>1e−12。沿用原搜尋與model-only移除：錨點與a不變，只移除target=0評分並正規化剩餘v；full/minus各自用原內部objective搜尋及接受，接受端點鎖定後才用共同完整v與固定尺度評分。這不是完整參與者LOO，不重訓，也不在搜尋中套標準化objective。

原T3及尺度實驗已揭露同分但品質相反的反例，故本輪不是未知假說的正式確認。新參數保留只能檢查既定機制的延伸，不能冒稱新實務任務或統計泛化。

## 2. 固定30個新解析設定

每類6案，前3開發、後3參數保留；先執行15開發並鎖報表，再執行15保留，不做中途調參。每案2模型、2維、target0、起點(0,0)、box[-1,1]²、錨點(1,0)、(-1/4,0)、a=(1/2,1/2)、eta=.1、最多10次縮步。poly(b,q)=1000+b*x0+q*x0²，所有probe／搜尋位置loss非負，target=0。

b依序為2/3、4/5、9/10、7/10、5/6、19/20；q依序為4/3、5/3、8/3、7/4、9/4、11/4。值及分組由fixtures固定。

| 類別 | 模型0、1 | v | 獨立診斷reference | 預期D符號 |
|---|---|---|---|---|
| effective_information | poly(1,0)、poly(-b,0) | .75/.25 | poly(1,0) | + |
| erroneous_information | 與上類完全相同 | .75/.25 | poly(-1,0) | − |
| effective_restraint | poly(1,2q)、poly(-1,0) | .5/.5 | poly(0,q) | + |
| erroneous_block | 與上類完全相同 | .5/.5 | poly(-1,0) | − |
| redundant_information | poly(1,0)、poly(1+b,0) | .5/.5 | poly(1,0) | 0 |

參數改變不等於獨立任務抽樣。同b的前兩類、同q的制衡／阻擋兩類，是有意設計的相同可觀測評分、不同正確答案對：若可觀測資料完全一樣，任何只靠它們的確定性算法必給相同分數。這用來界定資訊限制，不把已知答案塞進貢獻公式。

## 3. 操作及比較

1. 封存design、來源、fixtures、舊T3／尺度／錨點receipt並逐檔核對。先做技術測試，再對所有設定固定probe取得尺度並另鎖檔，然後才啟動搜尋。
2. 每案執行原未插樁full控制、相同full觀察及同輪minus，共3個單輪求解（90次，其中30次排除分支）。控制與觀察原查詢序列及結果須相同。removed模型不得進minus，common不得在端點鎖定前評分。
3. 原權重raw C、換算C／own／others、peer=others/(剩餘原v總和)四者只並列診斷；peer是其他模型部分的平均，不是已驗證替代法。品質D=reference(minus)−reference(full)只在端點固定後診斷。reference與探測均不進原求解。
4. 對每案每模型分別將probe與兩端點loss一致乘.1／10／100，固定端點重算，共180變體；不因倍增重搜，不宣稱搜尋尺度不變。檢查分解與尺度一致。
5. 每split／類別報告三分類(±1e−10)混淆與正負方向符合率、零作用、有效制衡、matched-pair可觀測相同性及own/others來源。不以總符合率掩蓋有害取得正值或有益取得負值。未定義必列null，不算零或從分母隱藏。

## 4. 技術與有效性驗收

技術硬gate：沿用12項尺度邊界測試及新增統計／matched pair／篡改測試；每案raw分支以獨立60位Decimal interpreter檢查梯度、端點、每trial接受及狀態；新分數以獨立Fraction quantile從raw重算；probe／端點／D與有理數多項式連結。核對來源、版本、探測鎖定時間與實際執行順序。故意C+1、scale+1、端點座標+.01及D改符號各案都必須被audit發現。

品質gate（必要而不充分）：原尺度每類6案及保留每類3案的C_norm符號均須符合D，零作用須近零；任一有害正值、有益負值或作用被歸零即不通過，不轉分配比例。此為機制反例篩選，通過也不證明實務品質／公平／誠實性。品質不通過不是執行失敗：保存全部數據、說明原因並停止擴充模型池；不調參把反例抹掉。

## 5. 成本、資料角色與停止

上限：90次單輪求解、搜尋API≤10000、probe1500、主流程≤120秒、產物≤100MB。另明列舊adapter內既有RMSE診斷所做模型／reference解析運算及核對算術，避免當成免費；不把CPU小解析延遲說成實務部署成本。

本輪只做小型解析情境及原引擎一致性，無新神經模型訓練／呼叫、pooled、真實truth資料或付款。解析reference等同已知答案的診斷設計，不作部署評價來源。若機制反例已失敗，停止升級真實團隊、分配及低成本主張；下一步先由使用者決定模型池要獎勵共同內部偏好，或引入可信的事後品質證據。若日後使用pooled，也只能在解與分數鎖定後離線驗證。

任何技術gate失敗立即保存failure、不做下游品質結論；不覆寫舊實驗、不更改alpha、錨點池、歷史solver或Notion。新結果是新探索性分析，絕不回填P3或其他正式確認。
