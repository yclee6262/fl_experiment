# 三池 T0／T1：履約規約與執行前驗證設計 v1

日期：2026-10-28。研究用規約，不是實際付款合約。授權：先實作T0、T1並整理結果。承接 `three_pool_contribution_validation_plan_v1_20261028.md`，本輪不進T2–T7。

## 1. T0決定與未決事項

本輪採固定任務費，不按呼叫次數計價。用整數「測試單位」避免浮點與捨入，沒有貨幣、費率或最佳池比例建議。示例總預算2000，基本池1000、錨點池500、模型池500。錨點／模型成果池維持未建立有效性及不可結算，未發放金額不回補基本池。

事前准入owner與服務承諾固定：A雙角色完整履約付300；B雙角色事前分段，錨點100、完整評分200；C只有錨點付100；D只有模型付200。基本費最大承諾900≤1000，預留100。A只有完成兩者才可領300，不能事後改成分段。B若只完成錨點可領100。所有別名先映射到同一owner，不按帳號重複領。

有效錨點＝已准入且具錨點承諾的owner，於要求期間交付指定slot，二維有限數值、每維在[-1,1]，具事前准入品質資格。品質資格是外部已確認的輸入假設，本模組不憑座標或loss重新認證；因此box可行不是品質有效性的證明。測試會涵蓋可行但缺資格的交付。沒有改善、負A、反向B或低模型E不影響履約驗收。

模型服務＝在指定期間、指定已授權請求、精確指定輸入與凍結版本回覆單一有限數值。每個模型owner有兩個指定邏輯請求，皆完成才算完整模型服務。從未授權的請求、系統重試、重複回覆不增加費用。允許先無效後於截止前補上有效回覆；但在授權期間對同一請求提供不同有效值（確定性違反），或使用不同版本（版本承諾違反），使本次模型服務不合格。不是用錯誤訊息或負貢獻扣款，而是事前明訂服務條件未完成。

### 範例時序

任務起點0、錨點截止100；模型請求簽發10、截止200；收帳截點300。deadline等號可接受。晚交、不在授權期間、超出收帳截點的事件列明原因，不算履約。收帳之前模型完成後又發現授權期間版本／確定性違反，該服務仍不合格；這是收帳前驗收，沒有執行後追回金額。

withdrawal在可信收件時間生效；同時間的交付視為已退出。退出前完整交付的服務保留已成立資格，退出後交付不補計。原子雙角色退出時未完成兩者則不成立完整費用；分段者只保留退出前完成的已約定階段。模型版本／確定性義務也只涵蓋退出前的有效服務窗口。

若任務實際無可行錨點，尚未完成錨點交付；failure_notice保留原因但不偽造完成。已約定分段且模型已完成者仍依分段規則處理。若未來要支付無解搜尋的努力費，需要另立服務承諾，本規約沒有該項。

## 2. 事件與信任邊界

合約、准入owner、owner別名、品質資格、授權請求及received_tick須由可信系統保存，不是參與者自行宣告。事件按可信received_tick與event_id排序，不採用客戶端聲稱時間；同一owner退出時間取最早有效退出事件。

相同event_id與完全相同內容視為冪等重播；相同ID不同內容視為證據衝突，整批不輸出影子金額，不能採先到者以掩蓋矛盾。不同ID但同一服務內容只計一個slot／請求；多交有效錨點也不增加固定費。同owner別名可共用原合約請求，不創造新資格或名額。

unknown_owner、不具角色、錯slot、錯query輸入、未知請求、無效格式、NaN／Infinity、超界、未到簽發時間、晚交、退出後交付、failure_notice及缺資料各留明確原因。NaN／Infinity在研究輸入用明確字串標記以維持JSON標準，不得變成有效數值。未完成狀態與影子可付0分開保存，不把缺資料當品質差或貢獻0。

無數位簽章或真人身分認證實作；假定registry與收件事件來源可信。不能由別名去重通過宣稱抗Sybil、抗串通或能驗證參與者自行提供的時間與版本資訊。事件相同與帳本確定性也不是端到端實際轉帳的exactly-once保證。

## 3. 可執行驗收

T0合約驗證：schema/version、整數非負預算／費用（bool不視為整數）、三池總和、owner與別名唯一、角色及請求合法、時間順序、維度／box、固定版本、合格品質旗標、原子／分段政策均須明確。最大固定基本承諾≤R0，否則拒絕合約，不按比例削減既有保障。

T1輸出：每個事件的處置及原因、每個owner的角色狀態與已完成請求、完整／部分／未完成／退出原因、影子基本費、基本池最大承諾／支出／餘額、成果池reserved且payment=null。實際轉帳永遠false。不能把成果池null寫成已判定貢獻0。

預算性質：每人基本影子費介於0與事前最大承諾；Σ基本費≤Σ最大承諾≤R0。因此三池保留款與實際模擬基本費合計不超總預算。缺交付的錢留在原池，不按人數重分。參與者貢獻診斷不進函式決策；示例的A/E/B僅作完全忽略的diagnostics。

## 4. 執行前固定的實驗

1. 手工標記情境：完整履約、負貢獻、無改善、反向作用、低成果品質但具服務准入資格；原子／分段／單角色、部分交付、無可行錨點；NaN／超界／錯維度／錯輸入／未授權／晚交；模型版本與確定性違反；重播、不同ID重複、owner別名、多交slot、未知owner；退出前／後／同時間；deadline邊界與收帳後事件；資料缺漏與failure_notice。
2. 窮舉：A與B分別對錨點是否有效、兩個請求是否有效、是否提前退出四個布林維度全組合，共32案。預期費用在執行engine前寫入golden輸入，不以engine回填。
3. 事件等價性：對所有可結算案做順序反轉、完全重播及加入未知owner／未授權事件，金額與履約狀態不變；負／正／零diagnostics互換不影響付款。事件數與忽略原因可不同，不要求整份輸出相同。
4. 合約拒絕：預算不足、總和錯誤、負費／小數／bool、重複owner／別名、缺版本、重複請求、未知policy等；ID衝突與未知事件type整批拒絕。拒絕輸出保留，不冒稱已完成結算。
5. 獨立reference不匯入engine或共用其資格判定函式，從原始合約／事件另算角色完成及金額，與人工golden及保存輸出比對。對結果故意改金額／狀態，稽核必須拒絕。
