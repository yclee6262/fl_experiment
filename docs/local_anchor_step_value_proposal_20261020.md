# 單步錨點增益累積：可行性與實驗提案

日期2026-10-20。回應使用者希望累積「哪個錨點讓當下這一步更好」，再比較LOO效果與成本。這是方法設計與既有軌跡的幾何預查；沒有新增模型查詢，尚未取得此方法的增益分數或有效性結果。

執行後更新（2026-10-20）：使用者已授權並完成本方法實作及小型比較，成本門檻通過、效果門檻未過。見 [實驗結果](local_anchor_step_results_20261020.md)。以下保留執行前設計；凍結副本另存實驗目錄。

## 定義

對原custom每個已接受步t，固定原位置x_t、全部評分模型與alpha、目前secant／dynamic模式，以及原步實際接受距離s_t。原錨點分量v_kt與合成g_t均可從已保存紀錄取得。

只拿掉錨點k的方向分量，將剩餘方向權重正規化，形成 `g_without_k=(g_t-v_kt)/(1-a_k)`；沒有刪掉k的評分模型，也沒有更新alpha。沿此新方向試走原s_t，得到z_without_k。這是固定原軌跡的單步測試，不從此處接續新路徑或重新退火。

同一把內部搜尋尺L評分；若替代試走未下降，依接受規則留在x_t，故有效替代誤差為 `min(L(x_t),L(z_without_k))`。剩餘方向小於原停止閾值時，以不移動處理；不足一個錨點則未定義。相同步長走出box者標示不能比較，不裁切、重縮步或填0。

主單步分數：

`J_kt = min(L(x_t), L(z_without_k)) - L(x_(t+1))`。

主累積分數 `A_k=sum_(原軌跡已接受步t) J_kt`。正值表示在這組固定局部比較下，有k較好；負值表示不用k的替代步更好。直接加總，不再乘步長、不擬合歷史係數、不取絕對值、不根據結果改正負。分開保存正／負及每步明細。

此為沿完整團隊原軌跡的錨點邊際增益。各J不是不重複的改善配額，不能保證sum_k J等於當步總改善；跨步累積可能重複計入相近作用，不等於最終品質的因果分解。一次移除所有角色、改走新路徑的C_custom_full仍是不同對象，必須實驗比較，不能預先宣稱等價。

## 成本如何公平比較

主探索正常baseline實測8,448模型輸入samples，完整移除額外實測24,672。單步方法預估最多額外3,869，相對baseline約+45.8%，相對完整移除額外部分約15.7%。若以共同baseline加上歸因計，估算12,317 vs 33,120 samples，約節省62.8%。以上只是輸入工作量估算，不是新方法已實測的耗時或API calls。

這輪研究可讀現成LOO結果而不重新求解；但比較演算法成本仍列從頭產生參考的原成本，不能將讀快取的0成本與新方法新查詢直接混比。另分研究實際增量、baseline、錨點查詢、LOO、離線evaluator及磁碟／載入成本。batch呼叫數與輸入samples分開，快取命中亦記錄，不能只用合併API數宣稱免費。

## 建議最小驗證

1. 先實作離線單步重建／評分，不修改原solver或讓額外回覆影響原路徑；核對原錨點分量、單位化、接受規則、box、缺失與快取語義。
2. 4個舊pilot只驗證計算與成本；固定公式後才計20案主探索。所有A保存／hash後才配對既有C。pooled不進J、A、原路徑或試步接受；truth只診斷。
3. 主指標為每團隊Spearman(A,C_custom_full)的均值／分布及seed bootstrap區間；次要列方向／near-zero描述、原始幅度差但不預設兩尺等尺度。alpha與上一版方向推力S作固定比較，不挑勝者改主方法。
4. 同時報每案額外samples、calls、運算及端到端耗時、峰值儲存；與原custom及完整移除分別比較。
5. 可考慮的探索進階條件：兩情境有效團隊覆蓋>=90%、平均團隊內Spearman>=0.5且探索95%CI下界>0；共同baseline加歸因的輸入評估量至少比baseline加全LOO省50%，實測耗時也須更低。這些是待凍結的設計建議，不是老師指定或已達成結果；本方法不預設仍能符合先前「baseline只增加10%」目標。
6. 任一技術或效度／成本條件不符，停止並交付，不改權重、步長、正負或追加seed到過線。通過也只是舊資料探索，需另立新資料確認，不能直接部署或刪人。
